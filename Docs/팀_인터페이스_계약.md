## 1. 지금 확정된 것 (변경하려면 사전 협의)

```csharp
public enum ToolType { FixedLine, FreeBody }

public struct Stroke                  // 단순화가 끝난 최종 포인트
{
    public ToolType Tool;
    public List<Vector2> Points;      // 월드 좌표, 최소 2개
    public float Length();            // 잉크 소모량
    public bool IsValid { get; }
}

public struct PivotJoint              // 회전축 = 연결 정보 (잉크 소모 없음)
{
    public int StrokeA, StrokeB;      // -1(PivotJoint.WorldIndex) = 월드 고정
    public Vector2 Anchor;
}

public class Solution                 // 한 판의 그림 전체 (시간 축 없음)
{
    public List<Stroke> Strokes;
    public List<PivotJoint> Pivots;
    public float TotalInk();
    public Solution Clone();
}

public enum SimOutcome { Clear, Fail, Stalled, Timeout }

public readonly struct SimResult
{
    public readonly SimOutcome Outcome;
    public readonly int EndStep;
    public readonly int Stars;
    public readonly float InkUsed;
    public readonly float MinGoalDist;   // 모든 Outcome 에서 채워짐
}

// 실행기 진입점 — 솔버·테스트·리플레이 검증이 전부 여기를 통과한다
SimResult SimRunner.Run(LevelData level, Solution solution, int seed, int maxSteps = 1800);
```

## 2. 담당자별로 필요한 것

### B — 잉크 파이프라인 + 장치 6종

**잉크 파이프라인**은 이 인터페이스를 구현한다. 시뮬 시작 전에만 호출되므로 결정론 부담이 없다.

```csharp
public interface IStrokeProcessor
{
    Stroke Process(ToolType tool, List<Vector2> rawPoints);
}
```

- 반환한 `Stroke.Points` 가 **물리·렌더링·리플레이 저장에 그대로 쓰인다.** 표시용 원본을 따로 남기지 않는다 (설계서 결정 7)
- 유효한 스트로크를 만들 수 없으면 `IsValid == false` 인 값을 돌려주면 호출부가 버린다
- 역방향(Stroke → 파라미터) 변환은 범위 밖이다

**장치 6종**은 이 인터페이스를 구현한다.

```csharp
public interface IStepLogic
{
    void Tick(int step, System.Random rng);
    bool HasPendingWork { get; }
}
```

- 시그니처에 경과 시간이 없다. 시간은 `step` 으로만 센다 (예: 폭탄 3초 = `step >= _armedStep + 180`)
- 난수는 인자로 받은 `rng` 만 쓴다. `UnityEngine.Random` 은 금지이며 테스트가 소스에서 잡아낸다
- `HasPendingWork` 는 조기 종료 판정용이다. 폭탄이 폭발을 기다리는 중이면 `true` — 이걸 빠뜨리면
  모든 바디가 잠든 순간 Stalled 로 잘려나가 폭탄이 터지지 않는다
- 등록은 `WorldBuilder` 의 3번 자리(지형과 스트로크 사이)에 **레벨 데이터 순서로** 들어간다

### C — LevelData / 레벨 에디터

```csharp
[Serializable]
public class LevelData
{
    public string Id;
    public float InkLimit;
    public Vector2 BallStart;
    public float BallRadius;
    public Vector2 GoalPosition;
    public float GoalRadius;
    public List<StaticSegment> Terrain;   // 리스트 순서 = 월드 등록 순서
    public float KillY;
}
```

- 지금은 "공 하나가 굴러가는 최소 코어"에 필요한 필드만 있다. **장치·별·장애물 배치가 들어올 자리**이며
  그 확장이 C 의 작업이다
- JsonUtility 직렬화 대상이므로 public 필드 + `[Serializable]` 만 쓴다 (프로퍼티·Dictionary·nullable 불가)
- 솔버가 이 데이터에서 **앵커**(부품을 놓을 만한 자리)를 뽑는다. 공 시작점·목표·별·장치 위치가
  기계가 읽기 좋은 형태로 들어 있어야 한다 — 좌표가 프리팹 안에만 있으면 솔버가 읽을 수 없다
- 리스트 순서를 바꾸면 물리 결과가 바뀐다. 에디터가 저장할 때 순서를 정렬하거나 뒤섞지 말 것

### D — 리플레이 / 자동 저장

리플레이 스키마는 아직 코드로 없다. 다만 **저장 대상은 확정**이다:

```json
{
  "levelId": "L017",
  "seed": 42,
  "gameVersion": "0.3.1",
  "strokes": [ { "tool": "FixedLine", "points": [[1.2, 3.4]] } ],
  "pivots":  [ { "a": 0, "b": 1, "anchor": [2.0, 1.5] } ]
}
```

- 저장하는 것은 **물리에 투입된 최종 `Stroke`** 다. 단순화 전 원본이나 솔버 파라미터가 아니다.
  재생 시 상류 파이프라인을 다시 돌리지 않으므로 알고리즘이 바뀌어도 재현이 깨지지 않는다
- `seed` 없이는 재현되지 않는다 (폭탄 파편 등 시뮬 중 난수). 스트로크 + 시드 + 버전이 3종 세트다
- `visualPoints` 같은 표시 전용 필드는 만들지 않는다 — 렌더링도 같은 스트로크를 쓴다
- 재생은 `SimRunner.Run` 과 같은 경로다. 유저 리플레이와 솔버 리플레이가 재생기 하나를 공유한다

## 3. 코어를 건드릴 때의 규칙

`SimWorld` / `WorldBuilder` / `Judge` / 계약 타입은 결정론 테스트가 초록불이 된 시점부터 동결이다.

1. 수정하면 EditMode 결정론 테스트를 다시 돌린다
2. 계약 타입 변경은 영향받는 사람에게 먼저 공유한다
3. 코어에 다음이 들어오면 테스트(`CoreSourceGuardTests`)가 소스를 읽어 실패시킨다 —
   `Time.deltaTime`, `Time.time`, `Time.timeScale`, `UnityEngine.Random`, `WaitForSeconds`,
   `FixedUpdate`, `DateTime.Now`, `Guid.NewGuid`
4. 물리를 전진시키는 곳은 `SimWorld.Step()` 하나뿐이다. 다른 경로를 만들지 않는다
