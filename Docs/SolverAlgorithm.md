# 솔버 알고리즘 — 확정 사항과 미결 사항

휴리스틱 맵(결정 2)과 탐색(결정 3)의 구현 범위를 정리한다.
목적은 **구현 전에 선택지를 전부 닫는 것**이다.

## 0. 전체 구조

두 층이고, 시뮬이 도는 방식이 서로 다르다.

|  | 맵 빌드 | 탐색 |
|---|---|---|
| 공 시작 | 셀의 대표 상태 (모든 셀) | 항상 `level.BallStart` |
| 놓는 것 | 후보 **하나** | 노드가 가진 **집합 전체** |
| 언제 | 레벨당 한 번, 캐시 | 매 요청 |
| 산출 | `h: BallCell → int` | `Solution` 또는 실패 + 통계 |

```
0.  h맵 빌드 (캐시 히트면 건너뜀)   → h맵
1a. 기저 시뮬                        → 궤적(앵커), 뿌리 노드
1b. 첫 배치 시도                     → 자식 노드, 열린목록
2.  n번째 시도 반복                  → 열린목록 갱신
3.  종료                             → Solution 또는 실패 + 통계
```

## 1. 맵 빌드 단계

`C` = 셀 수, `P` = 셀당 후보 수.

| # | 단계 | 입력 | 산출 | 반복 | 구현 |
|---|---|---|---|---|---|
| 0-1 | 격자 열거 | `LevelData`, 양자화 설정 | 모든 `BallCell` | 1회 | `BallGrid` 는 위치 축만 셈 |
| 0-2 | 역양자화 | 셀 1개 | 대표 상태 `(위치, 속도)` | `C` | **없음** |
| 0-3 | 무배치 시뮬 | 대표 상태, `LevelData`, seed | 궤적 | `C` | **임의 시작 상태 진입점 없음** |
| 0-4 | 비용 0 간선 | 궤적 | `c → ci` 비용 0 | `C` | `CollectFree` |
| 0-5 | 후보 생성 | 셀 위치, 격자 설정 | `Primitive` 목록 | 위치 셀당 1회 | `PrimitiveCandidates` |
| 0-6 | 배치 시뮬 | 대표 상태 + 후보 1개 | 궤적 | `C × P` | 0-3 과 같은 문제 |
| 0-7 | 비용 1 간선 | 궤적 | `c → ci` 비용 1 | `C × P` | `CollectPlaced` |
| 0-8 | 간선 병합 | 위 전부 | `Dictionary<CellEdge,int>` | 누적 | `CellEdgeCollector` |
| 0-9 | 역인접 색인 | 간선 맵 | `도착 → [(출발, 비용)]` | 1회 | **없음** |
| 0-10 | 목표 씨앗 | `LevelData` | `h = 0` 인 셀 집합 | 1회 | **없음** |
| 0-11 | 0-1 BFS | 색인, 씨앗 | `h: 셀 → int` | 1회 | **없음** |
| 0-12 | 통계·캐시 | `h`, 격자 | ∞ 비율, 캐시 엔트리 | 1회 | **없음** |

- 0-3/0-4 와 0-6/0-7 은 셀마다 붙어 도는 한 쌍이다. 궤적 버퍼는 하나를 `Clear` 하며 재사용한다.
- 후보는 셀의 **위치 부분에만** 의존한다. 같은 위치를 공유하는 속도 셀들은 후보 목록이 같으므로 위치당 한 번만 만든다.
- 비용은 0-6 에 몰린다. 최적화를 논한다면 거기만 보면 된다.
- 간선 맵은 산출물이 아니라 중간물이다. BFS 후 버린다. 캐시에 저장하는 것은 `h` 뿐이다.

## 2. 탐색 단계

| # | 단계 | 입력 | 산출 | 반복 |
|---|---|---|---|---|
| 1-1 | 기저 시뮬 | `LevelData`, seed | 궤적, `SimResult`, 뿌리 노드 | 1회 |
| 1-2 | 뿌리 f 계산 | 뿌리 궤적, h맵 | 열린목록에 뿌리 1개 | 1회 |
| 1-3 | 노드 선택 | 열린목록 | 최소 f 노드 | 매 시도 |
| 1-4 | 앵커 추출 | 노드 궤적 | 셀 집합 | 노드당 1회 |
| 1-5 | 후보 생성 | 앵커, 격자 설정 | 후보 목록 | 노드당 1회 |
| 1-6 | 필터 | 후보, 궤적, 소진 커서 | 미시도 · 교차하는 후보 | 매 시도 |
| 1-7 | 하나 선택 | 위 목록 | 후보 `p`, 커서 전진, **부모 재삽입** | 매 시도 |
| 1-8 | 잉크 검사 | 누적 잉크 + `p` | 통과 / 초과면 자식 없음 | 매 시도 |
| 1-9 | 배치 시뮬 | `노드.Primitives + [p]`, seed | 궤적, `SimResult` | 매 시도 |
| 1-10 | 클리어 판정 | `SimResult` | 성공이면 `Solution` | 매 시도 |
| 1-11 | 자식 삽입 | 자식 궤적, h맵, 잉크 | 열린목록에 자식 1개 | 매 시도 |
| 1-12 | 종료 판정 | 열린목록 | 비었으면 실패 + 통계 | 매 시도 |

1-3 ~ 1-11 이 반복 단위다. 한 바퀴에 시뮬이 정확히 하나 돈다.

## 3. 확정된 것

- **간선은 `c0 → ci`.** 궤적 중간의 `ci → cj` 는 넣지 않는다. 그건 프리미티브가 이미 놓인 상태에서만 성립하는데 맵은 미배치 기준이다.
- **비용은 0 또는 1.** 간선 하나가 배치 하나에 대응하므로 2 이상이 나올 자리가 없다. 그래서 0-1 BFS 로 충분하고 다익스트라가 필요 없다.
- **맵은 레벨당 하나, 미배치 기준.** 노드마다 맵을 두지 않는다. 정확도를 버리고 비용을 택한 트레이드오프다.
- **안내값 전용.** 허용성·일관성이 성립하지 않으므로 최적성 근거나 컷으로 쓰지 않는다. 탐색 순서에만 쓰면 틀려도 느려질 뿐 답을 잃지 않는다.
- **`f` 는 비단조.** 자식의 f 가 부모보다 작을 수 있다. 낙관 보너스가 f 를 깎기까지 한다. 의도된 것이다.
- **셀 속도는 방향 8 × 크기 4.** `VX = 방향x × 크기`, `VY = 방향y × 크기` 로 필드 추가 없이 32(+정지 1)셀. 8방향 분류는 `tan(22.5°)` 비교라 `atan2` 가 없고, 수평·수직이 구간 한가운데라 각도 경계 스냅이 필요 없다.
- **노드는 궤적 대신 앵커 셀 집합을 들고 있는다.** 궤적 원본을 노드마다 복사하면 열린목록 크기만큼 메모리가 든다.
- **소진 기억은 커서 정수 하나.** 후보 목록의 순서가 결정적이므로 `커서 == 길이` 가 소진 판정이다. `HashSet` 이 필요 없다.
- **부모 재삽입 구조.** 후보 하나를 꺼낼 때마다 부모를 큐에 되돌린다. "가지 닫기"와 "부모로 복귀"가 별도 코드 없이 여기서 나온다.
- **시도 1회 = 시뮬 1회.** D0 의 무작위 기준선과 비교하는 단위다.

## 4. 결정해야 할 것

| # | 항목 | 선택지 | 메모 |
|---|---|---|---|
| D1 | 궤적 셀들의 h 를 접는 방식 | (a) **최소** (b) 도착 셀 (c) 평균 | 조회 대상은 궤적 셀 전부(=앵커)다. 선택지는 접는 함수다. (b)는 목표를 스치고 엉뚱한 데서 멈춘 경우를 못 본다. (c)는 목표와 무관한 긴 구간이 값을 희석해 궤적이 길수록 불리해진다. **(a) 권장** |
| D2 | 노드 중복 제거 범위 | (a) 한 노드 안에서만 (b) 전체 탐색에서 집합 해시로 | `{p,q}` 가 순서 두 가지로 두 번 생긴다. (b)면 닫힌 집합이 하나 필요하다. D1 완료 조건 "같은 후보 재추출 안 됨"의 해석 문제 |
| D3 | 목표 씨앗의 경계 셀 | (a) 셀 중심이 원 안 (b) 셀이 원에 걸치면 포함 | (b)면 h 가 낙관 쪽으로, (a)면 비관 쪽으로 기운다 |
| D4 | ∞ 페널티 상수 | 값 미정 | 컷이 아니므로 유한값이어야 한다. `int.MaxValue` 는 `g + h` 에서 오버플로 |
| D5 | h → 잉크 환산 | "평균 프리미티브 잉크"의 정의 | 후보 격자의 크기 단계 평균인지, 실측 평균인지 |
| D6 | 낙관 보너스 형태 | `상수 / (1 + 시도횟수)` 등 | 상수 0 이면 순수 탐욕 (D5 완료 조건) |
| D7 | 맵 캐시 키 | (a) `WorldHasher` (b) `LevelData` 전용 해시 | `WorldHasher` 는 `world.Bodies`(Rigidbody2D)만 훑어 **정적 지형이 빠진다**. 살아 있는 월드의 현재 스텝을 찍는 결정론 검사용이라 레벨 신원용으로 부적합 |
| D8 | 맵 빌드 방식 | (a) 전체 선빌드 (b) 지연 생성 | 레벨을 한 번만 검증하면 빌드가 전체 비용을 지배한다. V2 결과에 달렸다 |
| D9 | 속도 구간 경계 | 현재 임시값 `정지 0.5 / 비율 3 / 4단계` | V1 실측 전까지 근거 없음 |
| D10 | 위치 셀 크기 | 공 지름 확정 여부 | 결정 2 의 근거는 "그보다 잘게 쪼개면 물리적으로 구분되지 않는다" |
| D11 | 후보 격자 설정 공유 | 맵과 탐색이 같은 설정을 써야 한다 | 다르면 h 가 탐색이 놓을 수 없는 배치를 전제하거나, 탐색의 실력을 과소평가한다. 한 군데서 잡아 양쪽에 넘기는 구조 필요 |

## 5. 검토·실측해야 할 것

| # | 항목 | 왜 |
|---|---|---|
| V1 | 기저 시뮬 몇 판의 **속도 분포** | D9 의 근거. 상한과 저속 구간 밀도가 같이 나온다 |
| V2 | 맵 빌드 비용 (`C`, `P`, 시뮬 1회 시간) | D8 판단의 근거. `C × (P+1)` 회가 감당 가능한지 |
| V3 | 간선 메모리 최고점 | 셀당 수백 간선 × 수만 셀이면 수백 MB. 빌드 중 최고점이며 BFS 후 버린다 |
| V4 | `Quantize(역양자화(c)) == c` 왕복 | 안 맞으면 간선의 출발 셀이 엉뚱한 곳에 찍혀 그래프가 조용히 어긋난다 |
| V5 | ∞ 비율과 실제 오판률의 상관 | F2 지표로 쓰려면 상관이 있어야 한다 |

## 6. 막고 있는 것 (구현 선행 순서)

1. **임의 시작 상태 시뮬 진입점** — `SimRunner` 가 공을 `level.BallStart` 에서만 출발시킨다. 없으면 0-3·0-6 이 둘 다 못 돌고 맵이 아예 안 만들어진다. **가장 시급하다.**
2. **역양자화** — 셀 → 대표 상태. 방향×크기 인코딩 기준으로 새로 쓴다. V4 를 같이 박는다.
3. **속도 축 포함 셀 열거** — `BallGrid` 는 위치 축만 센다.
4. 이후 0-9 ~ 0-12 (색인 · 씨앗 · BFS · 통계).

## 7. 현재 구현 상태

- `BallCell` — 속도가 방향×크기 라벨. 완료
- `BallQuantizer` — 방향 8 × 크기 4. 구간값은 임시(D9)
- `BallGrid` — 위치 축만. 속도 축 열거 필요
- `CellEdge` / `CellEdgeCollector` — `c0 → ci`, 비용 0/1, 겹치면 최소 비용. 완료
- `PrimitiveCandidates` — 위치를 받아 조합을 돌려준다. D11 확인 필요
- 맵 빌더 · BFS · 탐색 — 없음
