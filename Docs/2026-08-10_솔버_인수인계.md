# 솔버 인수인계 — 2026-08-10

WBS 5번(탐색 골격)과 9번(맵을 h 자리에 꽂기)이 함께 끝난 시점의 상태다.
다음 세션은 이 문서만 읽고 이어갈 수 있어야 한다.

## 지금 어디까지 왔나

**GapPuzzle 이 풀린다.** 맵에서 뽑은 h 를 탐색에 꽂아 54,152 시뮬 만에 선 셋으로 풀었다.
맵 없이는 20만 시뮬로도 깊이 3에 닿지 못했다.

| | 맵 없음 (D0) | 맵 있음 |
|---|---|---|
| 결과 | 예산 소진, 못 품 | **Solved · 선 3** |
| 시뮬 | 200,000 | 54,152 |
| 최대 깊이 | 2 | 3 |
| 최소 목표 거리 | 1.149 | 0.742 (임계 0.75) |
| 시뮬당 | 1.13ms | 5.70ms |

맵 빌드는 1,465,980 시뮬 · 547초(깊이 3)다. 즉 **맵이 자기가 살려낸 탐색보다 27배 비싸다.**
한 판만 검증할 거면 손해지만, 맵 없이는 답 자체가 안 나오므로 비교 대상이 없다.
값을 하려면 캐시(C7)로 여러 번 재사용해야 한다.

## 구조

```
CellGraphBuilder   레벨을 굴려 도달 집합·간선·이기는 셀을 모은다 (코루틴, 9분)
      ↓
HeuristicMap       이기는 셀에서 간선을 거꾸로 0-1 BFS → 셀별 h
      ↓
SolverSearch       h 를 순위에 넣어 푼다 (코루틴)
```

용어는 이렇게 쓴다. 조어를 새로 만들지 말 것.

| 이름 | 정의 |
|---|---|
| 도달 집합 | 시작점에서 실제로 갈 수 있는 셀들 (`CellGraphBuilder.States`) |
| 간선 | 셀 → 셀 이동. 선을 놓았으면 비용 1, 중력만이면 0 |
| 이기는 셀 | h 를 시뮬 판정으로 직접 아는 셀. 무배치 Clear 면 0, 선 하나면 1 (`.Wins`) |
| h | 그 셀에서 목표까지 더 그어야 할 최소 선 개수 |
| 벌점 | h 를 모르는 셀에 주는 값. `Furthest + 1` |

### 알아 둘 설계 결정 넷

**순위는 사전식이다. 단위를 통일하지 않았다.**
1축 `KeyLines` = `g + h` (둘 다 선 개수), 2축 `KeyInk` = 누적 잉크(미터).
더하면 개수와 미터를 더하는 것이라 뜻이 없어진다.

**부모가 자식의 순위를 물려준다.** 노드는 자기 h 를 모른다 — 궤적이 있어야 알고 궤적은
굴려야 나온다. 자리 `c` 에 선 하나를 놓은 자식은 `(g+1) + (h(c)−1) = g + h(c)` 로 상쇄돼서,
굴려 보지 않고도 순위가 나온다. 실제 이득은 여기서 난다 — 노드 하나가 후보를 수만 개 내는데
그중 무엇을 먼저 볼지 고르는 근거가 `h(놓는 자리)` 다 (`SolverSearch.CompareCandidates`).

**탐색은 레벨 시작점에서 전체 배치로 굴린다.** 맵 빌더처럼 중간 상태에서 새 선만 놓고 굴리면
싸지만, 반환한 Solution 을 재실행했을 때 같은 결과가 난다는 보장이 없다 (D8 조건).

**h 는 순서를 정하는 데만 쓴다. 가지를 자르는 데는 절대 쓰지 않는다.**
과대평가를 막지 못하므로, 컷에 쓰면 풀리는 레벨을 못 푼다고 판정하게 된다.
벌점을 `∞` 나 큰 수로 두면 그 셀들이 영영 안 뽑혀 사실상 컷이 된다 — 그래서 `Furthest + 1` 이다.

## 다음 세션에서 가장 먼저 할 일

### 1. 빨간 테스트 둘 정리 (결정 필요)

지금 테스트 스위트에 항상 실패/건너뜀인 것이 둘 있다. 맵 없는 탐색을 쓰기 때문이다.

- `SolverSearchTests.퍼즐_레벨을_예산_안에_푼다` — 맵 없이 `Solved` 를 단정한다. **항상 빨간불.**
  D0 기준선 기록용이었고 그 값은 이 문서와 노션에 남았다. 지우는 쪽을 권한다.
- `SolverSearchTests.찾은_풀이를_재실행하면_클리어한다` — 맵 없이 돌려서 풀이가 없어 **항상 Ignore.**
  맵을 넘기게 고치면 실제로 돌아간다. 그러면 D8 완료 조건이 처음으로 직접 검증된다.

D8 자체는 지금도 간접적으로는 덮여 있다. 탐색이 `Solved` 를 내는 조건이 "레벨 시작점에서 전체
배치로 굴려 Clear" 이고, 코덱 왕복 경로는 `내보내는_풀이가_굴린_배치와_같다` 가 따로 못박는다.

### 2. `SolverConfig.MapDepth` 를 3으로

지금 4인데 아무도 안 쓴다 — 테스트가 전부 `maxDepth: 3` 을 명시로 넘긴다.
4번 문서가 "4는 근거가 없다"고 이미 지적했고, 실제로 300만 시뮬 안에 안 끝난다.

다만 3도 조건부다. **이 값은 사실상 "풀이가 몇 개짜리라고 가정하는가" 다.**
깊이 `D` 로 지으면 마지막 확장이 깊이 `D-1` 셀에서 "한 개 더로 이기는가"를 묻는다 →
`D` 개짜리 풀이를 찾는다. GapPuzzle 이 3개라 3이 맞았다. 선 넷이 필요한 레벨이면
깊이 3 맵에는 이기는 셀이 하나도 안 나오고 h 가 통째로 빈다.
이 성질을 주석에 적어 두는 것까지가 이 작업이다.

### 3. 노션 4번의 수치가 낡았다

`CellEdgeCollector` 결함(아래)을 고치면서 도달 집합 수치가 바뀌었다.
4번 정정 표의 깊이 3 값 `7,127 셀 / 1,353,204 시뮬` → 지금은 `5,876 셀 / 1,465,980 시뮬`.
간선은 `194,489 → 328,092` 로 늘었다. 4번을 다시 볼 사람이 헷갈리지 않게 갱신이 필요하다.

## 이번에 찾아 고친 결함 셋

**간선이 굴린 자리에서 안 뻗고 있었다.** `SimRunner.RunSampled` 는 `Step()` 뒤에 표본을 떠서
첫 표본이 10스텝째다. `CellEdgeCollector` 가 `trajectory[0]` 을 출발 셀로 삼고 있었으니,
실제 출발 셀에서 나가는 간선이 통째로 빠졌다. 나가는 간선이 없는 셀은 h 를 못 받는다.
→ 출발 셀을 인자로 받게 고쳤다. 고친 뒤 커버리지가 40.9% → 31.4% 로 **떨어져 보이는데**,
없어진 것이 근거 없던 값이다 (고치기 전에는 "값을 아는 셀 2,912" 가 "확장한 셀 2,412" 보다 많았다).

**시뮬의 절반이 재굴림이었다.** 부모가 자식 하나를 내고 물러나면 그 자식이 같은 순위로 바로
팝돼 부모를 궤적 캐시에서 밀어낸다. → 같은 순위 무리를 통째로 뽑고 물러나게 했다.
`시뮬 / 노드` 가 1.99 → 1.00 이 됐다.

**씬 기준선이 오염됐다.** `_baseScenes` 를 앞 단계의 언로드 대기분이 남아 있을 때 재서
실질 상한이 헐거워졌다 (절대 40개까지 떴다). → `SimScenes.Settle()` 이 씬이 더 안 줄 때까지
기다렸다 기준선을 잡는다. 지금은 절대 17개다.

## 조심할 것

**탐색에 정체 판정을 걸었다. 이건 손실 있는 변경이다.**
`PrimitiveTrial` 주석에 "탐색은 여기서 끊으면 판정이 바뀐다"고 적혀 있고 사실이다.
`Stalled` 가 `Timeout` 으로 나오지만 탐색은 `Cleared` 만 보므로 지금은 문제가 없고,
`Idle()` 이 대기 중인 장치가 있으면 시계를 세워 폭탄도 안 놓친다.
**하지만 이 판단은 GapPuzzle 에 장치가 없다는 사실에 기대고 있다.**
장치가 있는 레벨을 검증할 때 다시 봐야 한다. 안 걸면 시뮬 단가가 33ms 로 돌아간다.

**모든 수치가 레벨 하나에서 나왔다.** `TestLevels.GapPuzzle` 이 유일하게 풀 것이 있는 판이다.
"맵이 값을 한다"는 결론의 표본이 1이다.

**맵의 홉과 실제 풀이는 물리가 다르다.** 맵은 홉마다 선을 하나만 놓고 굴리므로 이전 선이
사라진 상태로 계산한다. GapPuzzle 은 세 선이 시간 순서대로 작동해서 맞아떨어졌다.
두 선이 **동시에** 있어야 풀리는 레벨(벽과 경사가 함께 홈통을 만드는 형태)이면
맵이 그 풀이를 못 본다. h 는 순서만 정하므로 탐색이 답을 잃지는 않지만 맵이 값을 못 한다.

## 남은 큰 질문

- **맵 캐시(C7)** — 14분짜리를 매번 다시 지을 수 없다. 맵이 값을 하려면 이게 있어야 한다.
- **시뮬 단가 5.70ms 의 정체** — D0 의 5배다. 씬도 아니고 판 길이도 아니다.
  깊이 3이라 월드에 프리미티브가 3개까지 들고 `FreeBody` 가 섞이는 것이 유력하지만 확인 안 됐다.
  `SolverReport` 에 평균 스텝과 절대 씬이 붙었으니 다음 실행에서 볼 수 있다.
- **풀이의 질** — 지금은 순위 순서로 처음 만난 답이다. h 가 과대평가를 막지 못하므로
  A\* 최적성 보장이 없고, 선을 더 적게 쓰는 풀이가 뒤에 남아 있을 수 있다.
  "얼마나 어려운가" 판정으로 넘어가면 다시 봐야 한다.
- **후보 공간의 앞부분만 본다** — h 순으로 훑으니 앞쪽 몇 계층만 건드리고 커서가 뒤까지 못 간다.
  지금은 그게 이득이지만, 답이 뒤에 있는 레벨에서는 반대로 작용한다.
