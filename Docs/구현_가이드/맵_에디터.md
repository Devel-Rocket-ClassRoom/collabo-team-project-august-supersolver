# 맵 에디터 구현 가이드

> **근거** — [팀_인터페이스_계약](../팀_인터페이스_계약.md) · **실제 코드** `Core/Contracts/LevelData.cs` · 샘플 `Assets/_Project/Levels/`
> **이 문서가 바뀌면** — 함께 볼 하위 문서는 없다 (말단)
> **`LevelData` 나 `DeviceData` 가 바뀌면 이 문서를 고쳐야 한다** — 스키마가 여기 그대로 실려 있다
> 전체 관계: [문서 지도](../README.md)

**만드는 것**: 레벨을 만들고 `LevelData` JSON 으로 저장하는 도구.
**산출물**: `.json` 파일. 그게 전부다 — 코어는 JSON 말고 아무것도 요구하지 않는다.

> 미션 요구: **"레벨 추가에 코드 수정이 필요하면 미충족"**.
> 에디터가 아무리 좋아도 결과물이 프리팹이나 씬 안에만 있으면 이 요구를 못 지킨다.
> 좌표는 반드시 기계가 읽을 수 있는 데이터로 나와야 한다.

참고할 실물이 저장소에 있다. **새로 쓰기 전에 이 둘을 먼저 열어볼 것.**

| 파일 | 용도 |

## 1. 스키마

```csharp
[Serializable]
public class LevelData
{
    public string Id;                     // "L001_Ramp"
    public float InkLimit;                // 그릴 수 있는 총 길이
    public Vector2 BallStart;
    public float BallRadius;
    public Vector2 GoalPosition;
    public float GoalRadius;
    public List<StaticSegment> Terrain;   // 붙박이 지형. { A, B } 선분
    public List<DeviceData> Devices;      // 장치 배치
    public float KillY;                   // 이 아래로 떨어지면 Fail
}

[Serializable]
public struct StaticSegment { public Vector2 A, B; }
```

**클리어 조건**은 코어가 계산한다 — 공 중심과 `GoalPosition` 의 거리가 `GoalRadius + BallRadius` 이하가 되는 순간이다.
목표에 콜라이더는 없다. 에디터에서 목표를 트리거 오브젝트로 만들 필요가 없다는 뜻이다.

`Devices` 는 [장치 추가 가이드](장치_추가.md)를 참고. 에디터 입장에서는 그냥 배열이고,
**종류별 파라미터가 무엇인지만 알면 된다.**

## 2. JSON 으로 저장하기

`LevelData.ToJson()` / `LevelData.FromJson(text)` 가 이미 있다. `JsonUtility` 기반이라 제약이 따라온다.

```csharp
File.WriteAllText(path, level.ToJson(prettyPrint: true));
```

### 반드시 알아야 할 함정

**`JsonUtility` 는 모르는 키를 조용히 무시하고, 없는 키를 기본값으로 채운다. 예외를 던지지 않는다.**

키 이름에 오타가 나도 파싱은 "성공"하고, 그 필드만 기본값인 엉뚱한 레벨이 만들어진다.
에디터가 직접 문자열을 조립하지 말고 **반드시 `ToJson()` 을 거칠 것.** 손으로 쓴 파일을
읽어들일 때는 값이 제대로 들어왔는지 확인하는 편이 안전하다.

### 쓸 수 없는 것

- 프로퍼티 (`{ get; set; }`) — public 필드만
- `Dictionary`, nullable, 인터페이스, 다형 타입
- 최상위 배열 — 반드시 클래스로 감싼다

필드를 추가할 일이 생기면 `[Serializable]` + public 필드 규칙만 지키면 된다.

## 3. 지켜야 할 규칙 두 가지

### ① 리스트 순서를 바꾸지 말 것

`Terrain` 과 `Devices` 의 **리스트 순서가 곧 물리 엔진의 바디 등록 순서**다.
등록 순서가 바뀌면 부동소수점 합산 순서가 바뀌고, **같은 레벨이 다른 결과를 낸다.**

에디터가 저장할 때 이름순 정렬, 좌표순 정렬, 해시맵 순회 같은 것으로 순서를 뒤섞으면 안 된다.
사용자가 배치한 순서를 그대로 유지한다. 중간 삭제로 생긴 구멍을 메우는 것은 괜찮지만,
**이미 저장된 레벨의 순서를 바꾸면 그 레벨로 저장된 리플레이가 전부 깨진다.**

### ② 좌표는 데이터로 내보낼 것

솔버는 레벨 데이터에서 **앵커**(부품을 놓아볼 만한 자리)를 뽑는다. 공 시작점·목표·장치 위치가
그 원료다. 씬 오브젝트의 `transform` 에만 있고 JSON 에 없으면 솔버가 읽을 수 없고,
그 레벨은 자동 검증 대상에서 빠진다.

## 4. 만든 레벨을 확인하는 방법

### 눈으로 — SimScrubber

씬의 아무 GameObject 에 `SimScrubber` 를 붙이고 플레이하면 슬라이더로 스텝을 넘기며
시뮬을 볼 수 있다. `SimScrubber.BuildCatalog()` 에 한 줄 추가하면 목록에 뜬다.

```csharp
new Entry("내 레벨", () => LevelData.FromJson(File.ReadAllText(path)), () => null),
```

### 판정으로 — SimRunner

```csharp
SimResult result = SimRunner.Run(level, solution, seed: 0);

result.Outcome        // Clear / Fail / Stalled / Timeout
result.EndStep        // 몇 스텝에서 끝났나 (60 스텝 = 1초)
result.MinGoalDist    // 공이 목표에 가장 가까웠던 거리
```

`solution` 에 `null` 을 넣으면 **아무것도 안 그린 상태**로 돌린다.
이때 `Clear` 가 나오면 그 레벨은 퍼즐이 아니다 — 솔버도 같은 검사를 0단계로 한다.

`MinGoalDist` 가 유용하다. `Fail` 이나 `Stalled` 가 났을 때 이 값을 보면
"아깝게 못 갔다"인지 "방향부터 틀렸다"인지 구분된다.

## 5. 하지 말 것

| | 이유 |
|---|---|
| 레벨을 프리팹·씬으로만 저장 | 솔버가 읽을 수 없다. 미션 요구 미충족 |
| 저장 시 리스트 정렬·재배치 | 물리 결과가 바뀐다 |
| JSON 문자열 직접 조립 | 오타가 조용히 기본값으로 흡수된다 |
| 목표·별에 콜라이더 부여 | 판정은 코어가 거리 계산으로 한다 |
| 좌표를 화면 픽셀 단위로 | 전부 월드 좌표(유니티 유닛)다 |
