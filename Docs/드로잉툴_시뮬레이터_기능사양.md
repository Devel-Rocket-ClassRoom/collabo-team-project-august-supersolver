## 설계 기준

| 항목 | 기준 |
| --- | --- |
| 좌표계 | 데이터·물리·잉크 전부 **월드 유닛**. 그릴 수 있는 영역은 `LevelDataArea.Calculate(level)` 이 준다 — 공·목표·지형을 감싸는 상자에 마진 2wu. **고정 크기 설계 박스는 쓰지 않는다**(솔버가 쓰는 영역과 갈라지면 자동 검증이 거짓 양성을 낸다). 카메라는 그 영역이 다 보이도록 fit-inside 하고, **fit 기준 rect 는 화면 전체가 아니라 상/하단 밴드를 뺀 캔버스 영역**이다 — 화면 전체로 맞추면 세이프 에어리어가 큰 기기에서 영역이 밴드에 가린다 |
| 화면 | 세로 고정. 한 화면 고정(팬/줌 없음). 영역이 레벨마다 다르므로 **화면 스케일도 레벨마다 다르다** |
| 세이프 에어리어 | **UI 밴드에만 적용한다.** 카메라 **뷰포트**는 화면 전체다. 다만 캔버스 rect 가 `SafeAreaRoot` 의 자식이라 **fit 결과(orthographicSize·위치)는 인셋을 탄다** — 노치가 큰 기기는 그림이 조금 작게 보인다. 인셋 영역은 밴드 배경을 밖으로 넘치게 깔아 덮는다(UI 캔버스에 풀스크린 배경을 까는 방식은 그리기 영역까지 덮으므로 금지). 노치와 홈 인디케이터 인셋은 각각 독립이다 |
| 단위 원칙 | 인체공학 값(탭·offset·핀 반경)은 **dp + `Screen.dpi` 런타임 환산**. dp 는 dpi 를 통일하는 게 아니라 **dpi 차이를 픽셀 수로 흡수해 물리 길이를 고정하는 단위**다(`1dp = 1/160인치 = 0.159mm`). 손가락 크기가 기기와 무관하므로 조작 값은 이쪽이어야 한다. 데이터 품질 값(최소 거리·ε·최소 획 길이)은 **월드 상수** — 저장되는 점 밀도를 기기 독립으로 만들기 위함. **씬의 UI 치수는 dp 가 아니다** — `CanvasScaler` 가 폭 기준(match=0)이라 1080폭 정규화 단위이고, 실 dp 는 기기마다 달라진다. 두 체계를 같은 이름으로 부르지 않는다 |
| 콜라이더 | FixedLine=`EdgeCollider2D`, FreeBody=세그먼트별 사각형 `PolygonCollider2D`(속 빈 와이어). 자기 교차·닫힌 도형 허용. 공·장치 위 그리기 허용 — 겹침 반동도 결정론적이라 솔버와 일치한다 |
| 획 렌더러 | `LineRenderer`, 시각 두께 0.12wu(=FreeBody 물리 두께). 화면의 선과 콜라이더가 일치해야 한다 — 스무딩으로 곡선을 보정하는 방식(SpriteShape 등)은 쓰지 않는다 |
| Undo | **전체 스냅샷(Memento).** 액션(획·회전축·초기화)마다 `Solution.Clone()` push. 단위는 "마지막 액션 1개" |
| 저장 | `persistentDataPath/solutions/{StageId}.json`, Play 누를 때 |
| 직렬화 | JsonUtility 유지 + `Solution` 에 `Version(int)` 추가(계약 변경이라 팀 협의 후). 왕복 무손실은 테스트로 증명하고, 깨질 때만 표기를 바꾼다 |
| 실패 판정 | 자동 복귀 없음. `Judge` 의 Fail·Stalled 를 배너로 표시하고 재시도는 수동 |

**시작값 상수** (플레이테스트로 일괄 튜닝)
최소 거리 0.06wu · RDP ε 0.05wu · 최소 획 길이 0.25wu — `DrawConstants`
탭 8dp · offset 24dp · 핀 히트 반경 = 탭 환산치 · 최소 터치 타겟 48dp — `ScreenConstants`
데드존 10dp 는 씬이 소유한다(`DeadZone` 26 정규화 단위). 코드가 덮어쓰지 않는다

**아키텍처 제약**
- 입력 파이프라인은 MonoBehaviour 밖 **순수 C#** — 레이트 독립성을 기기 없이 합성 궤적으로 검증하기 위함
- 상태 전이는 컨트롤러 하나가 소유한다. UI 는 이벤트만 던진다
- 입력·UI 코드는 Core 밖에 둔다. Core 의 InputSystem·UI 참조 금지는 테스트로 강제한다
- 데이터 계약 변경(Version 필드)은 1회로 묶는다

## 잉크 규칙

작업 여러 개에 걸쳐 있어 여기 모아 둔다.

- **길이 비례.** 항상 `Stroke.Length()` 재계산 값이 진실이고, 획 확정 시 잔량을 이 값으로 스냅한다
- **Stroke 에 잉크량 필드를 두지 않는다** — 같은 점 배열이면 재계산 결과가 비트 단위로 같아 되돌리기 완전 일치가 성립한다
- 잔량 = `InkLimit − Solution.TotalInk()` **재계산**이다. 별도 환급 로직을 두지 않는다 — 되돌리기·롤백 모두 이 하나로 성립한다
- 그리는 중 차감은 **프리뷰 근사**. 필터를 통과한 세그먼트 길이 기준
- 표시는 **바 형태, 숫자 없음**
- **잔량 0 도달 시 그 지점에서 획이 끊긴다.** 경고·사전 경고 없음. 잔량 0 에서 PointerDown 하면 획이 시작조차 되지 않고 시각 피드백도 없다
- **끊긴 획의 유효성**: 끊긴 지점까지가 정상 Stroke 다(롤백 아님). 단 끊긴 길이가 최소 획 길이 미만이면 롤백이 우선한다
- **부동소수 잔여값**: 최소 획 길이 미만의 잔량은 0 으로 간주한다
- 회전축 도구는 잉크를 쓰지 않는다 — 잔량 0 에서도 동작한다

## 우선순위 (MoSCoW)

**우선순위지 순서가 아니다.** 착수 순서는 아래 「작업 순서」를 따른다.

**Must** — 화면 레이아웃과 도구 선택 UI · 입력 처리 · 획 관리와 저장 · 모드 전환 상태 머신 · 잉크 리소스

**Should**
- 다시 실행(Redo) — 되돌리기만으로 게임은 성립한다. 되돌리기 완성 후 그 위에 얹는다
- 도구별 Stroke Material (기능적 구분은 Must, 미적 품질만 Should)

**Could**
- UI 눌림 효과 (선택 상태 표시와는 별개)
- 손가락 위치 그림자 / 터치 인디케이터
- 앱 백그라운드 전환 시 자동 일시정지
- 홈 복귀 후 그린 획 유지
- 모드 전환 시 하단 UI 페이드

**Won't now**
- UI 청각 피드백 · 드로잉 전용 bgm · 스킨
- **홀딩 제스처로 도구 UI 대체** — v2 재검토. 그리다 멈춘 것과 의도적 홀딩의 구분이 어렵고, 궤적 단순화와 충돌한다(멈춘 구간에 점이 뭉쳐 결과 왜곡)
- 닫힌 도형 속 채우기 — 속 빈 와이어로 시작한다. 필요해지면 와이어를 유지한 채 채움 path 만 추가(additive fill)한다

## 작업 상세

### 1. 프로젝트 설정 🟡

**남은 것** — `GameSimDriver` 를 씬에 배치
**끝난 것** — 세로 고정, `AppBootstrap` 의 `Application.targetFrameRate` 설정

`targetFrameRate` 를 명시하지 않으면 모바일 기본값 30fps 라 120Hz 기기도 30 으로 돈다.

### 2. 계약 변경 — `Solution.Version` ❌

**내용** — `Solution` 에 `Version(int)` 을 추가한다. **계약 변경이라 팀 협의 후 진행.**

JsonUtility 는 모르는 키를 무시하고 빠진 키를 기본값으로 채운다. 버전이 없으면 스키마가
조용히 어긋난다.

**검증** — 임의 float 좌표 왕복 → `Points` 비트 일치 · `TotalInk` 일치 (EditMode)

### 3. 레이아웃·도구 UI 골격 ✅

**구역**

| 구역 | 그리기 모드 | 시뮬레이션 / 일시정지 |
| --- | --- | --- |
| 상단 | 설정 · 플레이 | 설정 · 일시정지(또는 재개) |
| 상단 아래 | 잉크 잔량 | 잉크 잔량 |
| 캔버스 | 드로잉 영역 | 드로잉 영역 (동일 크기) |
| 하단 | 도구 3슬롯(회전축 슬롯은 단독 핀 / 월드 고정 2모드) · 초기화 · 되돌리기 · 다시 실행 | **재시도 단독** |

**조건**
- 캔버스는 두 모드에서 고정. UI 는 그 위에 오버레이한다
- **캔버스 rect 는 상/하단 밴드 높이의 종속값이다.** 밴드를 바꾸면 캔버스도 바뀐다
- 하단 구역은 제거하지 않고 **내용만 교체**한다. 높이가 유지되어야 캔버스가 모드 간 동일하다
- 상/하단 밴드 배경은 **입력을 먹는다.** 버튼 사이 빈틈에서 획이 시작되면 안 된다
- **재시도 버튼은 하단 전체 폭**을 차지한다. 가장 자주 눌리므로 탭 타겟을 최대로 확보한다
- 하단 툴바 위쪽에 **데드존 10dp**(무반응 여백)를 둔다
- 세이프 에어리어는 UI 루트에만 적용한다
- **모든 터치 타겟은 48dp 이상**(기획 「UI 규격」, 단서 없음 — 전 버튼 대상). 지원 하한 기기에서 정규화 단위 **133 이상**이어야 한다. 현재 도구 3종 160 · 나머지 140. `TouchTargetAuditTests` 가 씬을 직접 읽어 강제한다
- **지원 하한은 화면 폭 2.45인치**(16:9 5.0인치). 기획서에는 물리 크기 규정이 없고 `최소 지원 API 26 · 스마트폰 기준` 만 있어, 그 시기 소형 폰에서 유도한 값이다. 기획이 하한을 명시하면 `TouchTargetAuditTests.MinScreenWidthInches` 를 바꾼다
- `CanvasScaler` 가 폭 기준이라 버튼의 실 dp 는 **화면 물리 폭에만 걸린다** — 해상도와 dpi 는 약분돼 사라진다. `dp = 정규화값 × 160 × 물리폭인치 / 1080`
- `ActionGroup` 은 ContentSizeFitter 가 가로 Unconstrained 라 **폭이 자동으로 안 늘어난다.** 버튼 크기를 바꾸면 `sizeDelta.x`(= 버튼×3 + 간격×2)도 같이 고친다. 안 고치면 버튼이 그룹 밖으로 넘친다

### 4. 좌표·카메라 계층 ✅

**내용** — 플레이 영역 fit-inside 카메라(두 모드 공통), dp↔월드 환산 유틸 + 상수 정의.
`Scripts/DrawingTool/Layout/` — `CanvasFit`(순수 산식) · `DeviceUnits`(dp 환산) ·
`ScreenConstants` · `CanvasCameraFitter`(씬 배선).

`Input/` 폴더에 두지 않는다. `InputSourceGuardTests` 가 그 폴더의 소스에서 `MonoBehaviour` 토큰을
잡는데 카메라 계층은 MonoBehaviour 여야 한다.

**조건**
- fit 기준은 **캔버스 rect**(밴드를 뺀 영역)다. 화면 전체가 아니다
- 캔버스 rect 의 중심은 화면 중심이 아니다(상/하단 밴드가 비대칭). 크기만 맞추고 카메라 위치를 안 옮기면 영역이 밴드 쪽으로 밀린다
- 카메라 값의 주인은 `CanvasCameraFitter` 하나다. 씬에 박힌 값은 진입 즉시 덮인다
- 제약 축은 캔버스와 영역의 종횡비가 정한다 — 여백이 좌우에 생길지 상하에 생길지 기기·레벨마다 다르다
- 영역 밖 여백은 시각적으로 구분한다 — "여기는 못 그린다"를 알려야 한다 (8번)
- **최소 획 길이(0.25wu) > 탭 임계값(8dp) 환산치**를 확인한다. 겹치면 판단 분기가 생긴다.
    이 부등식은 **플레이 영역 폭에 걸린다** — 폭이 커질수록 픽셀당 월드 거리가 커져 같은 8dp 가 더 긴 월드 길이가 된다.
    대표 기기 5종에서 **폭 11wu 까지 성립하고 12wu 부터 깨진다**(`DeviceUnitsTests`)

**검증** — `CanvasFitTests` · `DeviceUnitsTests`(EditMode).
전환 시 캔버스 rect 픽셀 동일은 `CanvasArea` 가 패널 교체와 독립이라 자명하게 참이므로,
실제 확인 대상은 **카메라 `orthographicSize`·`position` 이 변하지 않는 것**이다

### 5. 궤적 단순화 파이프라인 ✅

**내용** — 원본 궤적을 `최소 거리 필터 → 잉크 상한 절단 → RDP` 로 걸러 `Stroke` 하나로 만든다.

```
그리는 중  → 직전 확정점과 거리 ≥ 0.06wu 인 경우만 점 추가
           → 추가된 세그먼트 길이만큼 잉크 차감
           → 잔량을 넘기면 그 지점을 보간해 찍고 이후 점을 받지 않는다
손을 뗌    → RDP 단순화 (ε = 0.05wu)
           → 길이가 0.25wu 미만이면 롤백, 아니면 Stroke 확정
```

**조건**
- **두 계층 모두 순수 C#.** MonoBehaviour·InputSystem·UI 참조 금지
    - `StrokeBuilder`(상태 있음) — 획 시작 시 잔량을 받고 점을 하나씩 받아 필터 → 잉크 누적 → 절단. 프리뷰가 읽을 점 목록과 잔량을 노출한다
    - `StrokeProcessor : IStrokeProcessor`(무상태) — 확정 시 1회. RDP → Stroke → 최소 길이 판정
- 최소 거리 필터는 **프레임이 아니라 거리 기준.** 프레임 기준이면 120Hz 에서 점 밀도가 2배가 된다
- 잉크 절단은 **실시간**이다. 잔량 0 지점에서 프리뷰가 멈춰야 하고, 손 뗀 뒤 뒷부분이 사라지면 안 된다
- RDP 는 전역 알고리즘이라 실시간 적용이 원리적으로 불가능하다. 손 뗀 시점이 유일한 호출 지점이다
- **단순화 → Stroke 생성** 순서. 원본 점은 빌더 안에만 있다가 폐기된다. 원본을 Stroke 에 담으면 저장 데이터와 Undo 스택에 따라붙고 "원본/단순화" 두 표현이 공존한다
- RDP 의 거리는 **무한 직선이 아니라 선분** 기준으로 잰다. 직선으로 재면 왔던 길로 되돌아온 획에서 바깥 구간이 통째로 지워진다
- 절단점이 직전 점과 최소 거리 미만이면 찍지 않는다. 붙은 점을 남기면 마지막 세그먼트가 퇴화 콜라이더가 된다
- 최소 길이 미달은 `Points = null` 로 신호한다. `Stroke.IsValid` 가 계산 프로퍼티라 담을 필드가 없다
- 회전축 도구는 단일 점 입력이라 이 파이프라인을 타지 않는다

**검증**
- **점 밀도가 입력 레이트에 비례하지 않는다** — 같은 궤적을 120·240·480Hz 로 샘플링해 최종 점 개수의 최대/최소 비가 1.5 이하. 레이트를 타면 2.0 이 나온다
- **확정된 인접 점 간격이 항상 최소 거리 이상** — 밀도의 진짜 상한
- 같은 입력 2회 → 점 배열 비트 일치
- 최소 길이 미만 궤적 → 무효 `Stroke`, 잔량 변화 없음
- 잉크로 끊긴 획 — 최소 길이 이상이면 확정, 미만이면 롤백 우선
- `PPS.Core` 가 InputSystem·UI 를 참조하지 않는다

> 60/120Hz 를 나눠 재는 검증은 여기가 아니라 **6번**이다. 렌더 주사율은 터치 보고율을
> 바꾸지 못하므로, 파이프라인 입장에서 두 기기는 같은 입력이다.

### 6. 입력 프론트엔드 ⛔

**내용** — 터치·마우스를 받아 캔버스 좌표로 바꿔 파이프라인에 밀어 넣는다.
**최소 프리뷰 렌더가 여기 포함된다** — 획이 그려지는 걸 못 보면 아래 규칙을 검증할 수 없다. 품질은 8번.

**샘플 읽기**
- `EnhancedTouchSupport.Enable()` 을 호출한다. 안 하면 `Touch.activeTouches` 가 항상 비어 있다
- **`Touch.history` 로 프레임 사이 샘플까지 읽는다.** 터치 보고율(120~240Hz)이 렌더 프레임레이트보다 빠른데 프레임당 한 번만 읽으면 중간 샘플이 버려진다. Android `getHistoricalX/Y`, iOS `coalescedTouches` 와 같은 개념이다
- 화면→월드 변환은 `CanvasCameraFitter.ScreenToWorld` 하나를 통한다. 카메라 뷰포트는 화면 전체이고 캔버스 rect 는 fit 계산에만 쓰인다 — 두 개념을 섞지 않는다. `IsReady` 가 false 인 프레임에서는 좌표를 쓰지 않는다
- 에디터 마우스도 같은 경로. 차이는 offset 0 하나뿐이다

**탭 판정** — dp 비교는 여기서만 한다. 월드 단위 길이 판정은 5번 몫이고, 양쪽에 중복 구현하지 않는다
- 이동 거리 **< 8dp** → 탭
- 드로잉 도구: 탭 무시. 획 생성·잉크 소모 없음. 미세 콜라이더는 물리에서 터널링·지터를 일으킨다
- 회전축 도구: 탭이 정상 입력 (7번)

**터치 소유권** — Down 시점에 정해지고 Up 까지 바뀌지 않는다
- UI 에서 시작 → 끝까지 UI. 캔버스로 나가도 그려지지 않는다
- 캔버스에서 시작 → 끝까지 캔버스. UI 위를 지나도 획이 끊기지 않고 버튼도 눌리지 않는다
- **매 프레임 재판정 금지.** 툴바를 스치는 순간 획이 끊기고 도구가 바뀐다
- `EventSystem.IsPointerOverGameObject(id)` — **id 를 넘기는 오버로드**를 쓸 것. 인자 없는 버전은 터치에서 오동작한다. 신형 Input System 의 id 는 `Touch.touchId` 계열이라 구형 `fingerId` 와 값 체계가 다르다. `InputSystemUIInputModule` 이 부여하는 pointerId 와 맞는지 실기에서 확인한다

**경계 재진입** — **플레이 영역** 밖에서는 점을 추가하지 않고, 다시 들어오면 이어서 추가한다. 획을 강제 종료하지 않는다.
기준이 캔버스가 아니라 영역인 이유는 영역이 항상 캔버스 안에 들어가서다 — 캔버스 경계는 도달할 수 없다

**멀티터치** — first-touch-wins. 획 진행 중 두 번째 손가락은 완전 무시하고 첫 손가락을 뗄 때까지 잠근다. 팜 리젝션은 범위 밖(터치 면적 데이터 필요), 핀치 줌은 한 화면 고정이라 없다

**offset**
- 그리기 지점을 손가락보다 **화면 위쪽으로 24dp** 띄운다. 방향은 고정 — 이동 방향에 따라 회전시키지 않는다
- **클램프 기준은 캔버스 rect 가 아니라 플레이 영역이다.** 캔버스는 기기 종횡비에 따라 영역보다 크고 여백이 기기마다 달라, 캔버스 기준으로 잡으면 그릴 수 있는 범위가 기기마다 달라진다
- 클램프는 **offset 을 적용한 결과에만** 쓴다. 손가락 자체가 영역 밖이면 클램프가 아니라 점 미추가다 — 경계를 따라 의도치 않은 직선이 그려지면 안 된다
- 마우스는 offset 0

**검증**
- 에디터 마우스로 획이 그려진다
- **같은 기종 60Hz·120Hz 설정에서 같은 궤적 → 생성 점 배열 비트 일치.** 차이가 나면 `history` 를 안 읽고 프레임당 한 번만 읽는 것이다.
    **다른 기종끼리는 비교할 수 없다** — 화면→월드 계수가 해상도·인셋·레벨에 걸려 있어 같은 화면 궤적이 다른 월드 궤적이 된다. 기종을 가로지르는 검증은 월드 좌표를 합성해 주입하는 5번 몫이다
- 캔버스에서 시작 → 툴바 위를 지나 → 캔버스 복귀 → 획 1개, 도구 변경 없음
- 툴바 버튼에서 시작 → 캔버스로 드래그 → 획 0개
- 데드존에서 시작 → 아무 일도 일어나지 않는다
- 플레이 영역 밖으로 나갔다 들어온 궤적 → 획 1개, 밖 구간의 점 0개
- 획 진행 중 두 번째 손가락 → 획에 영향 없음
- 8dp 미만 탭 10회 → 획 0개, 잉크 == 초기값
- 플레이 영역 최상단에서 그려도 offset 적용 지점이 영역 밖으로 안 나간다
- 프리뷰(원본)와 확정선(단순화)의 튐이 눈에 띄지 않는다

### 7. 획 관리·Undo·회전축 ⛔

**되돌리기 / 다시 실행**
- **전체 스냅샷(Memento).** 액션(획 추가·핀 추가·초기화)마다 `Solution.Clone()` push. 역연산이 없어 핀 인덱스 무결성 문제가 생기지 않는다
- 단위는 **마지막 액션 1개**. 스택 깊이 무제한(스냅샷 하나가 KB 단위)
- **새 액션이 발생하면 Redo 스택 파기**
- **시뮬레이션 진입 시 Undo 스택 유지** — 재시도 후에도 되돌릴 수 있어야 한다
- 되돌리기는 **100% 전액 환급.** 잉크는 퍼즐의 예산이지 행동의 대가가 아니다. Undo 에 페널티를 붙이면 실험을 멈추고 시행착오 장르의 재미가 죽는다

**초기화**
- 스냅샷 Undo 라 자연히 되돌릴 수 있는 액션 1개다. push 후 획 목록을 비운다
- **확인 다이얼로그 없음.** 되돌릴 수 있으니 안전하고, 다이얼로그는 시행착오 루프에 탭을 하나 더 얹는다

**회전축(핀)**
- 탭 한 번이 정상 입력
- **월드 고정 여부는 플레이어가 고른다.** `단독 핀` / `월드 고정` 두 모드가 툴바 한 슬롯을 공유한다. 자동 판정은 쓰지 않는다 — 같은 자리를 탭했을 때 주변 획 개수에 따라 결과가 달라지면 의도를 표현할 수 없다
- 히트 반경(탭 환산치) 안의 획을 **최근에 그린 순**으로 정렬한다
    - `단독 핀` → 최근 2개 연결. 2개 미만이면 무효
    - `월드 고정` → 최근 1개 + `PivotJoint.WorldIndex`(-1). 0개면 무효
    - 무효면 아무것도 생성하지 않고 도구도 바뀌지 않는다
- 연결 대상에 FreeBody 가 하나도 없으면 생성하지 않는다 — `WorldBuilder` 가 정적↔정적 조인트를 조용히 버린다
- 핀 생성도 하나의 액션이다. Undo 스택에 쌓인다

**검증**
- 획 3개 → 되돌리기 3회 → 화면 빈 상태 && 콜라이더 0개 && **잉크 == 초기값 (완전 일치)**
- 초기화 직후 되돌리기 1회 → 이전 획 전부 복원
- FixedLine 2개가 겹친 지점에서 단독 핀 → 생성 0개 (FreeBody 없음)
- FreeBody 1개 위에서 월드 고정 → `PivotJoint(StrokeA = n, StrokeB = -1)`
- 반경 밖 빈 곳에 탭 → 생성 0개, 상태 변화 없음
- 잉크 잔량 0 에서 핀 생성 성공

- 도구별로 그려진 획이 시각적으로 구분되어야 한다. 색이 아니어도 되지만 구분자는 필수다
- 플레이 영역 밖 여백을 시각적으로 구분한다. 손가락은 움직이는데 선이 안 늘어나면 버그로 보인다

### 10. 상태 머신·UI 동작 ⛔

**상태** — `그리기` · `시뮬레이션` · `일시정지`

전이는 컨트롤러 하나가 소유한다. 핸들러에 전이 로직을 흩뿌리면 재시도×일시정지×Undo
조합에서 추적 불가능한 버그가 생긴다.

| From | 입력 | To | 부수 효과 |
| --- | --- | --- | --- |
| 그리기 | 플레이 | 시뮬레이션 | Solution 저장 → 물리 시작. Undo 스택 유지 |
| 시뮬레이션 | 일시정지 | 일시정지 | 물리 정지 |
| 일시정지 | 재개 | 시뮬레이션 | 물리 재개 |
| 시뮬레이션 / 일시정지 | 재시도 | 그리기 | 물리 오브젝트 초기 위치 복원(전파괴→재구축), **그린 획은 유지**. 진입 직전 선택돼 있던 도구를 복원 |

**상태별 허용 입력**

| 입력 | 그리기 | 시뮬레이션 | 일시정지 |
| --- | --- | --- | --- |
| 캔버스 드로잉 | O | X | X |
| 도구 전환 · 되돌리기 · 다시 실행 · 초기화 | O | X (숨김) | X (숨김) |
| 플레이 | O | – | – |
| 일시정지 / 재개 | – | O | O |
| 재시도 | X (숨김) | O | O |
| 설정 | O | O | O |

**재시도 vs 초기화**

| | 재시도 | 초기화 |
| --- | --- | --- |
| 물리 오브젝트 | 초기 위치 복원 | 초기 위치 복원 |
| 내가 그린 획 | **유지** | **삭제** |
| 잉크 | 유지 | 초기값 복원 |
| 노출 위치 | 시뮬레이션 모드 하단 | 그리기 모드 하단 |

**UI 동작**
- 그리기 도구·초기화·되돌리기·다시 실행은 시뮬레이션 진입 시 **숨김**. 비활성으로 남기지 않는다
- 모드 전환 시 하단 구역은 **연출 없이 즉시 교체**
- 선택된 도구는 selected 로 표시한다. 눌림 피드백(Could)과 별개의 **정보 표시**다
    - **색 하나로만 표시하지 않는다.** 배경 유무 + 아이콘 색처럼 두 채널을 겹친다 — 색약 사용자에게 현재 도구가 안 보인다(WCAG 1.4.1)
    - 표시가 버튼 rect 밖으로 넘치지 않게 한다
- `Judge` 가 Fail·Stalled 를 확정하면 **배너를 표시**한다. 상태 전이는 하지 않는다 — 재시도는 수동이다
- 클리어 시 보상 화면 (Mock & Stub)

## 완료 조건

빌드 버전(**IL2CPP, ARM64**)을 모바일 기기로 테스트한다. Unity 는 Android ARM64 에
IL2CPP 만 지원한다(Mono 는 ARMv7 전용). 에디터는 Mono 로 도므로 **부동소수점 결과가 배포
런타임과 다를 수 있어, 해시 검증은 기기 빌드에서도 한 번 돌린다.**

1. 직접 그린 Solution 으로 Play 를 눌러 시뮬레이션한다
    1. 클리어 시 보상 화면 (Mock & Stub)
    2. 실패 시 재시도 → 그린 획은 유지된 채 물리 오브젝트만 초기 위치로 복원
2. 되돌리기로 마지막 액션(획·회전축·초기화)이 되돌려진다
    1. 획 3개 → 되돌리기 3회 → 화면 빈 상태 && 콜라이더 0개 && **잉크 == 초기값 (완전 일치)**
3. 초기화로 그린 그림이 지워진다
    1. 초기화 직후 되돌리기 1회 → 이전 획 전부 복원
4. 2·3 을 여러 번 반복하고 다시 그려도 시뮬레이션 결과가 항상 같다
    1. Hash 비교 테스트로 증명한다
    2. 저장 → 로드 → 재시뮬레이션 Hash 도 동일 (직렬화 왕복 무손실)
5. 입력 처리
    1. **같은 기종** 60Hz / 120Hz 설정에서 동일 궤적 → **생성 점 배열 비트 일치**
        (다른 기종끼리는 화면→월드 계수가 달라 원리적으로 비교 불가)
    2. 캔버스 → 툴바 위 통과 → 캔버스 복귀 → 획 1개, 도구 변경 없음
    3. 툴바 버튼에서 시작해 캔버스로 나가는 드래그 → 획 0개
    4. 획 진행 중 두 번째 손가락 → 획에 영향 없음
    5. 8dp 미만 탭 10회 → 획 0개, 잉크 == 초기값
6. 레이아웃
    1. 그리기 ↔ 시뮬레이션 전환 시 **카메라 `orthographicSize`·`position` 이 변하지 않는다**
        (캔버스 rect 픽셀 동일은 `CanvasArea` 가 패널 교체와 독립이라 자명하게 참이다)
    2. 그림을 그린 뒤 Play 해도 획의 화면상 위치가 변하지 않는다
    3. 모든 터치 타겟이 지원 하한 기기(화면 폭 2.45인치)에서 48dp 이상 — `TouchTargetAuditTests`

## 미결정

| 항목 | 내용 | 대기 중인 결정 |
| --- | --- | --- |
| **`LevelDataArea` 가 아직 공용이 아니다** | `PrimitiveValidator.PlayArea` 가 같은 로직을 따로 갖고 있고 솔버·테스트가 전부 그쪽을 쓴다. `AreaMargin = 2f` 도 두 벌이다. 한쪽만 고치면 갈라지고, 그 순간 "솔버는 풀린다는데 플레이어는 못 그린다"가 복귀한다 | 코어·솔버 담당 — `PlayArea` 를 `LevelDataArea.Calculate` 로 위임 |
| **레벨이 가로로 길다** | L001 14.05×8.63(1.63:1) · L002 22×12.86(1.71:1). 캔버스는 0.83:1(세로)이라 fit-inside 하면 캔버스의 49~52%가 빈다. 더 심각하게 **폭 12wu 부터 탭 임계값(8dp)이 최소 획 길이(0.25wu)를 추월**해 "탭이냐 획이냐" 판단이 두 단위에서 갈린다 | 레벨 담당 — 세로 지향으로 재작성, 폭 상한 11wu |
| **배속이 사양에 빠져 있다** | 기획 「시뮬레이션 제어」가 "진행 중 일시정지와 **배속**을 지원"을 필수로 둔다. 상태 머신·UI 어디에도 자리가 없다. 코어는 이미 있다(`SimAccumulator.SpeedMultiplier` — 누적 시간만 조절하고 `FixedDt` 는 안 건드려 결정론 유지). **버튼과 전이만 없다** | 10번에 넣을지, 상단/하단 어디에 둘지 |
| **앱 전환 복구가 Could 에 있다** | 기획 「필요로 하는 기능」에 "자동 저장 및 복구 — 앱 전환이나 강제 종료 시에도 진행도가 손실 없이 복원"이 있다. 우리는 "백그라운드 자동 일시정지"·"홈 복귀 후 그린 획 유지"를 Could 로 뒀다. 다만 기획서의 "진행도"가 레벨 진척인지 그리던 획까지인지 모호하다 | 범위 확인 후 Must 승격 여부 |
| **손가락 가림 대책의 근거** | 기획 「그리기」가 "궤적을 굵게 표시하거나 **그림자**를 함께 그려"를 필수로 둔다. 우리는 그림자를 Could 로 두고 offset 24dp 로 대체했다. 기획서가 대체를 허용하되 **근거를 요구**하므로, 근거를 문서에 남기지 않으면 미충족으로 읽힌다 | offset 을 정식 대체안으로 승격할지, 그림자를 Must 로 올릴지 |
| PC 빌드 지원 | 에디터에서 마우스 offset 0 으로 동작하게만 만든다 | 마우스 정식 지원 / 키보드 단축키 / "게임 종료" 버튼 |
| 상수 튜닝 | 필터·ε·최소 획 길이·offset·핀 반경 시작값. **최소 획 길이 > 탭 환산치** 는 4번에서 확인 완료 — 플레이 영역 폭 11wu 까지 성립 | 플레이테스트 후 일괄 |
| 터치 Canceled | 시스템이 터치를 회수했을 때(알림·전화) 획을 확정할지 버릴지 | 사양에 없음 |
| 프리뷰 튐 보정 | 실제로 보일 때만 트레일링 윈도우 검토 | 선제 구현하지 않는다 |
