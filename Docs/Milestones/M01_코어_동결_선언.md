동결은 기술적 상태가 아니라 **약속**이다. 코드는 이 선언 전후로 한 글자도 달라지지 않는다.
달라지는 것은 **"이 코드를 바꾸려면 무엇을 거쳐야 하는가"** 뿐이다.

## 1. 동결 범위

### 잠기는 것

**계약 타입** (`Assets/_Project/Scripts/Core/Contracts/`)

`ToolType` · `Stroke` · `PivotJoint` · `Solution` · `SimOutcome` · `SimResult`
· `IStepLogic` · `IStrokeProcessor` · `LevelData` · `DeviceType` · `DeviceData`

**시뮬 실행부** (`Assets/_Project/Scripts/Core/Sim/`, `Core/Devices/`)

`SimWorld` · `WorldBuilder` · `ColliderFactory` · `Judge` · `WorldHasher`
· `SimAccumulator` · `SimRunner` · `DeviceFactory` · `BombDevice` · `DeterminismGuard`

특히 다음 둘은 **박제된 계약**이다.

- **월드 구축 순서** — 공 → 지형(레벨 데이터 순서) → 장치(레벨 데이터 순서) → 스트로크(리스트 순서) → 회전축(리스트 순서)
- **스텝 순서** — 로직 → 물리 → 판정 → 스텝 증가

### 잠기지 않는 것

여기에 적힌 것을 바꾸는 것은 **동결 위반이 아니다.** 적어두지 않으면 매번 물어보게 된다.

| 대상 | 누가 | 조건 |
|---|---|---|
| `LevelData` 필드 확장 (별·앵커 등) | C | 사전 공유 |
| 장치 스키마 + `BombDevice` | B | §4 |
| `ColliderFactory` 의 충돌 모델 | 코어 | §5 |
| `GameSimDriver` · `SimScrubber` | 누구든 | `Assembly-CSharp` 소속으로 **애초에 동결 범위 밖**이다. 다만 물리를 전진시키는 경로를 새로 만들면 안 된다 |
| 테스트 코드 | 누구든 | 추가는 자유. **삭제·완화는 리뷰 필수** |

## 2. 결정론의 유효 범위 ★

> **같은 입력이 같은 결과를 낸다는 보장은 동일 바이너리·동일 CPU 아키텍처 안에서만 성립한다.**

Physics2D(Box2D)는 플랫폼 간 부동소수점 일치를 보장하지 않는다. 따라서

- 에디터(x64)와 Android 실기기(ARM64)의 결과가 갈릴 수 있다
- Unity 버전이나 Physics2D 설정이 달라져도 갈릴 수 있다 (설정 변화는 `DeterminismGuard` 가 검사한다)

**이것은 코어 결함이 아니다.** 실기기에서 리플레이가 어긋났다면 원인을 코어에서 찾지 말 것.
대응은 설계서 §2.2 의 **표본 검증**이다 — 대표 풀이 리플레이를 실기기에서 재생해 보는 QA 절차이며,
코어 수정이 아니다.

이 문장이 없으면 나중에 실기기에서 리플레이가 어긋난 날, 동결된 코드를 여는 것으로 시작하게 된다.

## 3. 변경 절차

코어를 바꾸려면 **셋 모두** 거친다.

1. **결정론 테스트 재실행** — **EditMode·PlayMode 양쪽**, 총 개수 / 통과 / 실패를 함께 기재
   - 결정론·판정·프레임 독립성은 전부 PlayMode 에 있다. EditMode 만 초록불인 것은 아무것도 검증하지 않은 것과 같다
2. **코드 리뷰 승인** — 승인 없이 머지하지 않는다
3. **계약 타입 변경 시 영향받는 사람에게 사전 공유**

이 절차는 `.github/pull_request_template.md` 가 체크박스로 강제한다.
템플릿과 이 문서의 내용이 어긋나면 **둘 다 안 지켜진다** — 고칠 때 함께 고칠 것.

### 재실행 조건

다음 시점에는 **결정론 테스트 전체를 다시 돌린다.**

- 팀원 B 의 장치가 처음 합류할 때 — A-1 매트릭스에 그 장치를 쓰는 케이스를 추가한다
- `ColliderFactory` 의 형상·충돌 처리가 바뀔 때 (§5)
- Unity 버전 또는 Physics2D 설정이 바뀔 때

## 4. 장치 스키마의 잠정성

`DeviceType` · `DeviceData` · `LevelData.Devices` · `BombDevice` 는 **자리를 잡아 둔 것(placeholder)** 이며,
장치 6종을 맡은 사람이 **자유롭게 바꾸거나 갈아엎어도 된다.** 그 변경은 동결 예외로 취급한다 —
결정론 테스트 재실행 + 리뷰만 거치면 되고, 새 동결 판정은 필요 없다.

지금 형태는 폭탄 하나를 태우기 위한 최소 골격이고, 종류가 늘면 공용 필드 하나로는 감당이 안 된다.

**바꿀 때 지켜야 할 것은 셋뿐이다.**

1. `JsonUtility` 가 다룰 수 있는 형태일 것 — public 필드 + `[Serializable]`, **다형 직렬화 불가**
2. **리스트 순서가 곧 로직 등록 순서이자 난수 소비 순서**라는 것
3. `DeviceType` 의 **enum 값을 재배열하지 말 것** — 정수로 직렬화되므로 순서가 바뀌면 이미 저장된 레벨 JSON 과 리플레이가 다른 장치를 가리킨다. 추가는 뒤에만

**`BombDevice` 는 새 장치의 본보기다.** 결정론 규칙 넷이 그 안에 다 들어 있다 —
rng 를 `Tick` 에서만 소비, 바디를 등록 순서대로 순회, 힘 대신 속도, 잠든 바디는 `WakeUp()` 명시 호출.
장치를 추가하는 지점은 `DeviceType` 값 하나와 `DeviceFactory` 의 switch 한 줄이다.

### 시드 축에 대하여

코어에서 `System.Random` 이 흘러가는 곳은 `IStepLogic.Tick` **하나뿐**이다.
따라서 **장치가 없는 레벨에서는 시드가 결과에 닿지 못한다.**
"장치 없는 레벨의 시드 테스트가 왜 없지"라는 질문이 나오면 답은 이것이다.

## 5. 충돌 모델의 한계

`ColliderFactory` 는 **정적 스트로크와 동적 스트로크를 다른 형태로** 만든다.

| | 콜라이더 |
|---|---|
| 정적 (`FixedLine` · 지형) | `EdgeCollider2D` — 두께 0 의 선 |
| 동적 (`FreeBody`) | 선분마다 반 두께 `FreeBodyHalfWidth`(0.06) 만큼 부풀린 `PolygonCollider2D` |

**나뉜 이유는 Box2D 가 edge ↔ edge 충돌을 만들지 않기 때문이다.** 자유 물체까지 edge 로 두면
공(원) 말고는 아무것과도 부딪히지 않고 지형을 그대로 통과한다.
정적 쪽을 edge 로 남긴 것은 상대가 원이든 다각형이든 충돌이 성립하고,
바꾸면 기존 레벨의 공-지형 해시 기준선이 흔들리기 때문이다.

**두께는 충돌을 성립시키기 위한 최소값이지 물리적 굵기가 아니다.**
질량은 여전히 두께 0 의 철사 모델로 계산한다 — 면적으로 질량을 잡으면 두께 상수를 건드릴 때마다
모든 레벨의 물리가 바뀐다.

### 남은 한계

**닫힌 형태의 속이 비어 있다.** 벽 자체는 두꺼워 통과할 수 없으므로 실질적으로 solid 처럼 동작하지만,
도형 안에 갇힌 물체가 생길 수 있고 아주 빠른 물체가 얇은 벽을 뚫을 여지가 남는다
(동적 스트로크는 `Continuous` 로 완화).

진짜 면적 채움이 필요해지면 볼록 분할로 교체하며, **그 교체는 동결 위반이 아니다.**

> **교체의 수용 기준**: 정적 스트로크와 **2점 직선 자유 물체의 해시 기준선이 그대로 유지될 것.**
> 이 둘이 흔들리면 기존 레벨·리플레이가 전부 무효가 되므로, 확장은 순수한 추가여야 한다.

### 프리미티브 대응 현황 (M03 참고)

| 프리미티브 | 현재 |
|---|---|
| 경사면 · 발판 · 벽 | 가능 (정적 폴리라인) |
| 그릇 | 가능 (열린 곡선) |
| 지렛대 | 가능 (동적 막대 + 회전축) |
| 바퀴 | 가능 (닫힌 다각형, 관성 `m·r²` 에 수렴) |
| 상자 | 가능 (닫힌 다각형, 벽이 두꺼운 껍데기) |

## 7. 함께 나가야 할 통보

선언과 별개로 **사람에게 전달해야 하는 것**이다. 저장소가 대신해 주지 않는다.

- **팀원 C** — `LevelData` 에 `Devices` 필드가 추가되었다. 공유 계약을 넓힌 것이므로 사전 통보 대상이다. 스키마는 placeholder 이며 레벨 에디터 작업과 함께 확정하면 된다 (§4)
- **팀원 B** — 장치를 추가하는 지점은 `DeviceFactory` 의 switch 한 줄이다. `BombDevice` 가 본보기이고, 절차는 [장치 추가 가이드](../구현_가이드/장치_추가.md) 에 있다
- **전원** — PR 템플릿이 생겼다. 코어를 안 건드리는 PR 은 해당 없는 블록을 지우고 쓰면 된다

파트별 인수인계 문서는 [Docs/구현_가이드/](../구현_가이드/) 에 있다.
