# 마일스톤

[솔버_설계서.md](../솔버_설계서.md) §10 "구현 순서(리스크 순)"를 실행 단위로 쪼갠 문서 모음.
번호 순서 = 착수 순서이며, **앞 마일스톤의 완료 조건을 채우기 전에 다음 마일스톤에 착수하지 않는다.**
리스크가 큰 것부터 배치했기 때문에, 순서를 바꾸면 뒤에서 발견된 문제가 앞의 모든 작업을 무효화한다.

| # | 마일스톤 | 기간 | 상태 | 완료 조건 요약 |
|---|---|---|---|---|
| [M01](M01_결정론_코어와_계약_확정.md) | 결정론 코어와 계약 확정 | 1~2주차 | 진행 중 | 결정론 자동 테스트 초록불 + 계약 타입 코드 확정 |
| M02 | 헤드리스 호스트 + 조기 종료 + 벤치마크 | 3주차 | 예정 | 배치모드 CLI 동작 + 스텝당 실측치 확보 |
| M03 | 프리미티브 + 무작위 탐색 엔드투엔드 | 4~6주차 | 예정 | 레벨 1개를 솔버가 자동 판정 (팀 첫 데모) |
| M04 | CEM 업그레이드 | 예정 | 예정 | 분포 학습 탐색으로 성공률 개선 |
| M05 | 난이도 2지표 + 분류 | 예정 | 예정 | 발상 난이도·실행 난이도 산출 및 등급 분류 |
| M06 | 다양성 클러스터링 + 리포트 export | 예정 | 예정 | 서로 다른 풀이 개수 산출 + 엑셀 결과표 |

M02 이후는 M01 완료 시점에 실측·상황을 반영해 상세 문서를 작성한다.
지금 확정하면 벤치마크 전 추정치를 계획에 박제하게 되므로 의도적으로 비워 둔다.

## 문서 규칙

- 파일명: `M{번호}_{제목}.md`
- 각 문서는 **완료 조건(DoD)** 을 검증 가능한 형태로 적는다. "잘 동작한다"가 아니라 "이 테스트가 통과한다"
- 범위 밖 항목을 명시한다. 마일스톤이 늘어나는 주된 원인은 범위가 흐린 것이다
