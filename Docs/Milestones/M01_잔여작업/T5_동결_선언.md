## 왜 선언이 필요한가

동결은 기술적 상태가 아니라 **약속**이다. 코드는 동결 전후로 한 글자도 달라지지 않는다.
달라지는 것은 "이 코드를 바꾸려면 무엇을 거쳐야 하는가"뿐이고, 그것이 적혀 있지 않으면 동결은 없었던 것과 같다.

저장소 안의 문서로 남긴다. 팀 채널 공지는 검색되지 않고, 나중에 합류하는 사람에게 전달되지 않는다.
채널 공지는 이 문서로 링크만 걸면 된다.

## 선언문에 반드시 들어갈 것

### 1. 동결 범위

무엇이 잠기는지 타입·어셈블리 단위로 명시한다.

- 계약 타입 — `Stroke` / `PivotJoint` / `Solution` / `SimOutcome` / `SimResult` / `IStepLogic` / `IStrokeProcessor` / `LevelData`
- 시뮬 실행부 — `SimWorld` / `WorldBuilder` / `Judge` / `ColliderFactory` / `WorldHasher` / `SimAccumulator` / `SimRunner`
- **잠기지 않는 것**도 함께 적는다. `LevelData`의 필드 확장(장치·별·앵커)은 팀원 C의 작업으로 예정되어 있고, `Build`의 장치 주입 인자는 그때 흡수된다. `ColliderFactory`의 형상 처리도 예정된 예외다(§5). 무엇이 확장 예정인지 적어두지 않으면 B·C가 매번 물어보게 된다

### 2. 결정론의 유효 범위 ★

> 동일 바이너리·동일 CPU 아키텍처 안에서만 보장한다.

이 한 줄이 빠지면 나중에 반드시 대가를 치른다. Physics2D는 플랫폼 간 부동소수점 일치를 보장하지 않으므로
에디터(x64)와 Android 실기기(ARM64)의 결과가 갈릴 수 있다. **이것은 코어 결함이 아니다.**

단서가 없으면 실기기에서 리플레이가 어긋난 날, 원인을 코어에서 찾다가 시간을 태우고
동결된 코드를 열게 된다. 대응은 설계서 §2.2의 표본 검증(대표 풀이 리플레이를 실기기에서 재생)이며,
그것은 QA 절차이지 코어 수정이 아니라는 것까지 적는다.

### 3. 변경 절차

동결 후 코어를 바꾸려면 전부 거친다.

1. 결정론 테스트 재실행 — **EditMode·PlayMode 양쪽**, 총/통과/실패 기재
2. 코드 리뷰 승인 (미션 요구: 리뷰 이력이 평가 항목)
3. 계약 타입 변경 시 영향받는 팀원에게 **사전** 공유

절차는 [T4](T4_테스트_실행과_리뷰_규약.md)의 PR 템플릿과 같은 내용이어야 한다. 두 곳에 다른 말이 적혀 있으면 둘 다 안 지켜진다.

### 4. 장치 주입 인자의 잠정성 ★

[T3](T3_장치_실행_경로_범위_결정.md)에서 `WorldBuilder.Build`에 `IStepLogic` 주입 인자가 추가되었다.
동결 범위에 들어가지만 **영구 설계가 아니므로** 그 사실을 적는다.

> `Build`의 `injectedLogics`는 **장치가 레벨 데이터에서 나올 때까지의 임시 통로**다.
> 로직 루프·`HasPendingWork`·rng 경로를 동결 전에 실행해 보기 위한 것이고, 출하 경로가 아니다.
> 장치 데이터 스키마(`LevelData`의 장치 필드, 종류 판별, 파라미터)는 팀원 B(장치 6종)·C(레벨 에디터)가
> 함께 정하며, 그때 이 인자는 흡수되거나 사라진다. 그 변경은 동결 예외로 취급한다 —
> 결정론 테스트 재실행 + 리뷰만 거치면 되고, 새 동결 판정은 필요 없다.

시드 축에 대해서도 한 줄 남긴다 — `_rng`는 `IStepLogic.Tick`에만 주입되므로
**장치가 없는 레벨에서는 시드가 결과에 닿지 못한다.** 이걸 적어두지 않으면
나중에 누군가 "장치 없는 레벨의 시드 테스트가 왜 없지"라고 다시 물어본다.

### 5. 충돌 모델의 한계 — `ColliderFactory` ★

질량 특성은 **동결 전에 고쳤다** (체크리스트 C-6). 폴리라인·곡선의 무게중심과 관성이 이제 맞는다.
남은 한계는 형상이 아니라 **충돌 모델**이므로, 그것만 정확히 적는다.

> `ColliderFactory` 는 **정적 스트로크와 동적 스트로크를 다른 형태로** 만든다.
>
> - **정적**(`FixedLine`·지형) — `EdgeCollider2D`, 두께 0 의 선
> - **동적**(`FreeBody`) — 선분마다 반 두께 `FreeBodyHalfWidth` 만큼 부풀린 `PolygonCollider2D`
>
> 나뉜 이유는 **Box2D 가 edge ↔ edge 충돌을 만들지 않기 때문이다.** 자유 물체까지 edge 로 두면
> 공(원) 말고는 아무것과도 부딪히지 않고 지형을 그대로 통과한다. 정적 쪽을 edge 로 남긴 것은
> 상대가 원이든 다각형이든 충돌이 성립하고, 바꾸면 기존 레벨의 공-지형 해시 기준선이 흔들리기 때문이다.
>
> 두께는 **충돌을 성립시키기 위한 최소값이지 물리적 굵기가 아니다.** 질량은 여전히
> 두께 0 의 철사 모델로 계산한다 — 면적으로 질량을 잡으면 두께 상수를 건드릴 때마다
> 모든 레벨의 물리가 바뀐다.
>
> 남은 한계는 **닫힌 형태의 속이 비어 있다**는 것이다. 벽 자체는 두꺼워 통과할 수 없으므로
> 실질적으로 solid 처럼 동작하지만, 도형 안에 갇힌 물체가 생길 수 있고 아주 빠른 물체가
> 얇은 벽을 뚫을 여지가 남는다(동적 스트로크는 `Continuous` 로 완화). 진짜 면적 채움이
> 필요해지면 볼록 분할로 교체하며, **그 교체는 동결 위반이 아니다.**
>
> 교체의 수용 기준: **정적 스트로크와 2점 직선 자유 물체의 해시 기준선이 그대로 유지될 것.**
> 이 둘이 흔들리면 기존 레벨·리플레이가 전부 무효가 되므로, 확장은 순수한 추가여야 한다.

| 프리미티브 | 현재 |
|---|---|
| 경사면 · 발판 · 벽 | 가능 (정적 폴리라인) |
| 그릇 | 가능 (열린 곡선) |
| 지렛대 | 가능 (동적 막대 + 회전축) |
| 바퀴 | 가능 (닫힌 다각형, 관성 `m·r²` 에 수렴) |
| 상자 | 가능 (닫힌 다각형, 벽이 두꺼운 껍데기) |

## 배치

`Docs/Milestones/M01_코어_동결_선언.md` 를 제안한다.
[M01 문서](../M01_결정론_코어와_계약_확정.md) §7이 동결을 예고하고 있으므로 그 옆에 두고 서로 링크한다.

EditMode/PlayMode 실행 수치. 나중에 "그때 정말 통과했었나"를 되짚을 때 필요한 것은 선언이 아니라 근거다.
