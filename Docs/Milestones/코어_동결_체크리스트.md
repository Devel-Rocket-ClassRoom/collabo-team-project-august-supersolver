# 코어 동결(Core Freeze) 검증 체크리스트

[M01](M01_결정론_코어와_계약_확정.md) 완료 판정 기준. 통과 시 코어(`SimWorld` / `WorldBuilder` / `Judge` / 계약 타입)를 동결하고 [M02](README.md)에 착수한다.

## 이 문서의 범위 — 코어 오너가 혼자 끝낼 수 있는 것만

동결의 목적은 **"팀원이 작업을 시작해도 코어가 흔들리지 않는다"를 보장하는 것**이다.
따라서 게이트에는 코어 오너가 단독으로 통제 가능한 항목만 넣는다. 남의 산출물이나 다음 마일스톤의
작업이 섞이면, 코어가 증명 가능하게 옳아도 동결이 되지 않는 교착이 생긴다.

**게이트에서 제외한 것과 그 행선지:**

| 제외 항목 | 이유 | 어디로 |
|---|---|---|
| 팀원 B의 장치 6종 구현 | B의 산출물 | 코어는 최소 장치 하나로 **실행 경로만** 덮는다 ([T3](M01_잔여작업/T3_장치_실행_경로_범위_결정.md)). 6종의 스키마·동작은 B의 작업 |
| 팀원 C의 레벨 에디터 산출물 | C의 산출물 | 코어는 손으로 쓴 샘플 JSON 하나로 로더 경로만 증명 ([T2](M01_잔여작업/T2_샘플_레벨_JSON_경로.md)) |
| 벤치마크 3수치·배속 환산 | 코어의 **성능** 특성이지 정확성 특성이 아니다. 동결이 막으려는 것은 정확성 회귀다. 측정 하네스는 헤드리스 호스트가 있어야 성립한다 | M02 완료 조건 |
| 팀 채널 동결 공지 | 저장소 밖 행위. 게시 여부를 코드로 검증할 수 없다 | 선언문을 저장소에 커밋하는 것까지가 게이트 ([T5](M01_잔여작업/T5_동결_선언.md)) |
| 실기기(ARM64) 재현 검증 | 플랫폼 간 부동소수점 일치는 Physics2D가 보장하지 않는다. 코어 결함이 아니다 | 표본 검증 QA 절차 (설계서 §2.2) |

## 채점 규칙

- 저장소에 **존재하고 실행·확인 가능한 것만** PASS. "구현 예정", "로컬에는 있음"은 FAIL
- 실행형 항목은 **EditMode와 PlayMode 결과를 모두** 제출한다. 결정론·판정·프레임 독립성 테스트는 전부 PlayMode에 있으므로, **EditMode만 초록불인 리포트는 A와 C를 하나도 증명하지 않는다**
- 실행 결과는 통과 개수만이 아니라 **총 개수 / 통과 / 실패**를 함께 적는다. 예외로 죽은 테스트는 "없는 테스트"와 구분되지 않으므로, 총계가 없으면 판정불가로 처리한다
- `판정불가`는 FAIL과 구분해 보고한다 (원인: 환경 부재 / 근거 부재 / 항목 해석 불가)
- **모든 항목 PASS일 때만 동결 가능.** FAIL 항목 목록이 곧 남은 작업 목록이다

## A. 결정론 증명

### A-1. 반복 실행 일치
- **내용**: 같은 `(LevelData, Solution, seed)`로 2회 실행하여 **매 스텝** `WorldHasher.Hash()`가 완전 일치
- **검증**: 아래 매트릭스를 테스트 코드에서 확인 + 실행

  | 케이스 | 입력 | 근거 |
  |---|---|---|
  | 1 | 빈 솔루션 | 기준선. 지형·공만으로 갈라지면 그 아래 전부 무의미 |
  | 2 | 고정선만 | 스트로크 바디가 등록 순서에 끼어드는 경우 |
  | 3 | **회전축 포함** | 조인트가 바디 등록 순서에 가장 민감하다. 이 케이스 없이는 결정론이 증명되지 않는다 |
  | 4 | **장치 포함** | 로직 루프와 rng 가 결과에 개입하는 유일한 경로 |
  | 5 | **장치 포함 + 시드 4개** | 시드가 결과에 실제로 **반영되는지**. 같은 시드 재현과는 다른 축이다 |

- **통과 기준**: 케이스 1~4는 스텝별 해시 완전 일치. 케이스 5는 반대로 **시드가 다르면 궤적이 갈라져야** 한다 — 시드를 무시하는 코어는 항상 같은 결과를 내므로 케이스 1~4를 완벽하게 통과한다
- **시드 축이 케이스 5에서만 의미를 갖는 이유**: 코어에서 `System.Random`이 흘러가는 곳은 [SimWorld.cs:91](../../Assets/_Project/Scripts/Core/Sim/SimWorld.cs:91)의 `_logics[i].Tick(step, _rng)` 한 곳뿐이다. **장치가 없는 레벨에서는 시드가 결과에 닿지 못하므로**, 장치 없는 케이스에 시드를 여러 개 매기는 것은 같은 시뮬을 여러 번 도는 것에 지나지 않는다
- **작업**: 케이스 3 → [T1](M01_잔여작업/T1_회전축_결정론_테스트.md) · 케이스 4~5 → [T3](M01_잔여작업/T3_장치_실행_경로_범위_결정.md)

### A-2. 재구축 독립
- **내용**: 같은 입력으로 "생성 → 실행 → 전파괴"를 반복했을 때, 사이에 **다른 월드를 끼워 만들었다 버려도** 매 회차의 스텝별 해시가 1회차와 동일
- **검증**: 테스트 코드 확인 + 실행
- **통과 기준**: 전 회차 해시 일치. 회차 수는 3회 이상이면 족하다 — 오염원(정적 카운터·캐시·풀)은 1회차와 2회차 사이에 이미 드러나며, 회차를 늘리는 것으로 새로 잡히는 결함은 없다. 중요한 것은 횟수가 아니라 **사이에 다른 월드를 끼웠는가**다
- **의미**: 되돌리기·재시도·솔버 반복 시도 전체의 기반 증명

### A-3. 프레임·청킹 독립
- **내용**: 동일 입력을 서로 다른 프레임 간격(30/60/120fps 상당)으로 구동했을 때 도달 스텝과 해시가 일치. 누적기를 거친 결과가 `Step()`을 직접 호출한 결과와 일치. 배속이 스텝 수만 늘리고 내용은 바꾸지 않음
- **통과 기준**: 전부 일치
- **기대치 주의**: 이 항목은 구조상 통과하기 쉽다. `Step()`은 외부 상태를 받지 않고 `Simulate(FixedDt)`만 부르므로 호출을 어떻게 쪼개든 결과가 같다. 실제 위험은 청킹이 아니라 **누적기가 `dt`를 건드리는 것**이고, 그것을 잡는 것은 배속 테스트다. 배속 케이스가 빠져 있으면 FAIL

### A-4. 해시 인프라
- **검증**: `WorldHasher`가 **독립 타입**으로 존재하고, 전 바디의 position/rotation/velocity를 **등록 순서 고정**으로 해시하는지 코드 확인
- **통과 기준**: 충족. 테스트 코드에 인라인으로 박혀 있으면 FAIL — 리플레이 실기기 표본 검증과 디싱크 디버깅이 같은 타입을 재사용해야 한다

### A-5. 해시 민감도 ★
- **내용**: 공 시작 위치를 미세하게(0.0001) 옮겼을 때 해시 궤적이 실제로 갈라지는지
- **통과 기준**: 갈라짐. **A-1·A-2·A-3가 이 항목 없이는 성립하지 않는다** — `Hash() => 0` 은 항상 같은 값을 뱉으므로 반복 실행·재구축·청킹 일치를 전부 통과한다. 해시가 상태를 반영한다는 증명이 없으면 위 세 항목은 아무것도 증명하지 않는다

## C. 코어 실행 경로 커버리지

> 동결의 의미는 "이 코드를 더 이상 만지지 않는다"이다. **한 번도 실행된 적 없는 경로를 동결하면,
> 그 경로의 결함은 동결 후에 발견되어 동결을 깨는 변경을 강요한다.** 그래서 코어 안의 분기는
> 동결 전에 실행되었거나, 명시적으로 범위에서 빠져 있어야 한다.

### C-1. 회전축 생성 경로
- **검증**: `CreatePivot`과 그 하위 `Resolve` / `PickHost`가 테스트에서 실제로 실행되는지
- **통과 기준**: 실행됨. 스트로크 간 연결과 `PivotJoint.WorldIndex`(월드 고정) 두 형태 모두 커버. **조인트가 바디를 붙잡고 있다는 직접 검사**가 함께 있을 것 — 조인트 생성에 실패해도 스텝별 해시는 재현되므로 결정론 테스트만으로는 잡히지 않는다
- **현재**: `PivotTests` + `DeterminismTests` 작성 완료, 실행 검증 대기 → [T1](M01_잔여작업/T1_회전축_결정론_테스트.md)

### C-2. JSON → 월드 구축 경로
- **검증**: 저장소에 커밋된 `.json` 파일을 읽어 `LevelData.FromJson` → `WorldBuilder.Build`로 월드가 구축되는지
- **통과 기준**: 성공. JSON에 공 시작점·목표 위치·잉크 제한이 포함될 것 (앵커 생성의 원료). C# 코드로 만든 `LevelData`만으로는 부족하다 — 미션 요구는 **"레벨 추가에 코드 수정이 필요하면 미충족"** 이며, 그 증명은 파일에서 읽는 경로가 있어야 성립한다
- **작업**: [T2](M01_잔여작업/T2_샘플_레벨_JSON_경로.md)

### C-3. 장치 실행 경로
- **결정**: **지금 구현한다. 단 계약 확장 없이** (2026-08-01 확정). `WorldBuilder.Build`에 `IStepLogic` 주입 인자 하나만 더하고, 가짜 폭탄은 테스트 픽스처에 둔다. 장치 데이터 스키마는 코어가 선점하지 않는다 — B·C의 작업이다
- **검증**: 다음이 테스트에서 실제로 실행되는지
  - `WorldBuilder`의 로직 등록 루프
  - `SimWorld.Step()`의 로직 루프 (`_logics[i].Tick`)
  - `Judge`의 `HasPendingWork` 분기 — 전 바디가 잠들어도 대기 중인 장치가 있으면 `Stalled`가 미뤄지는가
  - 주입된 `rng`가 소비되고 그 결과가 시뮬에 반영되는가 (A-1 케이스 5)
- **통과 기준**: 위 전부 + 장치가 **바디 목록을 늘리지 않을 것**. 늘어나면 해시 순서가 밀려 기존 레벨의 결정론 기준선이 통째로 어긋난다
- **잠정성 주의**: `Build`의 주입 인자는 **장치가 레벨 데이터에서 나올 때까지의 임시 통로**다. 출하 경로가 아니라는 사실이 동결 선언문에 적혀야 한다 → [T5](M01_잔여작업/T5_동결_선언.md)

### C-4. 편집↔시뮬 2상태 분리
- **검증**: 편집 상태(월드 없음)에서 물리가 진행되는 경로가 없는지 코드 구조로 확인
- **통과 기준**: 월드는 시작 시점에만 생성되고, 월드가 없을 때 전진 호출이 무해할 것. 편집 중 자동 진행 경로가 존재하면 FAIL

### C-6. 자유 물체가 임의 형상으로 동작한다 ★
- **왜 동결 조건인가**: `ColliderFactory`는 동결 범위 안이다. 그런데 M03 프리미티브(경사면·그릇·상자·바퀴)는 **반드시** 곡선과 닫힌 형태를 전개한다. 이걸 못 다루는 채로 잠그면 M03 착수와 동시에 동결을 깨야 하고, 그건 동결이 아니다

**(1) 충돌** — 자유 물체가 다른 것들과 실제로 부딪히는가

- **Box2D 는 edge ↔ edge 충돌을 만들지 않는다.** 지형·고정선·자유 물체가 전부 `EdgeCollider2D` 이면 자유 물체는 공(원) 말고 아무것과도 부딪히지 않고 지형을 그대로 통과한다
- **검증**: 자유 물체가 ① 지형 ② 고정선 ③ 다른 자유 물체 위에 각각 멈추는지, ④ 공이 자유 물체 위에 얹히는지
- **통과 기준**: 4가지 전부. 기존 테스트가 **공과의 상호작용만** 봐서 이 구멍을 오래 못 잡았다 — 공은 원이라 edge 와 정상 충돌한다. 자유 물체가 주어가 되는 검사가 반드시 있어야 한다

**(2) 질량 특성** — 폴리라인에서도 무게중심과 관성이 맞는가

- 무게중심이 포인트의 산술 평균이 아니라 **선분 길이 비중**일 것 — 같은 형상이 샘플링 밀도에 따라 다르게 움직이면 안 된다
- 관성이 곧은 막대 공식(`m·L²/12`)이 아니라 **선분별 평행축 정리의 합**일 것 — 둘레 `L` 인 고리에서 막대 공식은 약 3.3배 과대다
- 퇴화 스트로크(모든 점이 겹침)에서 관성이 0 이 되지 않을 것 — 0 은 NaN 을 부르고, NaN 은 해시를 타고 번져 원인 추적이 불가능해진다

**통과 기준(공통)**: 위 전부 + **정적 스트로크와 2점 직선 자유 물체의 결과가 이전과 동일할 것.** 이 둘이 흔들리면 기존 레벨·리플레이의 해시 기준선이 통째로 어긋난다. 정적 스트로크를 `EdgeCollider2D` 로 남겨 두는 이유가 그것이다

### C-5. Outcome 4종 관측
- **검증**: 최소 레벨에서 `Clear` / `Fail` / `Stalled` / `Timeout`이 각각 재현되고, `MinGoalDist`가 **모든 Outcome**에서 초기값(∞)도 NaN도 아닌 값으로 채워지는지
- **통과 기준**: 4종 관측 + `MinGoalDist` 생존. 이 값이 죽어 있으면 M04의 CEM이 학습 신호 없이 헤매게 되고, 그 원인을 솔버 버그로 오인하기 쉽다. 동결 전에 박제한다

### D-1. 실행 결과 제출 형식
- **검증**: EditMode·PlayMode 각각의 실행 결과가 저장소에 커밋되어 있고, **총 개수 / 통과 / 실패**가 확인 가능한지
- **통과 기준**: 양쪽 다 존재하고 실패 0. 어느 한쪽만 있으면 판정불가
- **작업**: [T4](M01_잔여작업/T4_테스트_실행과_리뷰_규약.md)

### D-2. 변경 절차 강제
- **검증**: "코어 변경 시 결정론 테스트 재실행 + 코드 리뷰 승인"이 PR 템플릿 등 **저장소 안의 형태**로 존재하는지
- **통과 기준**: 존재. 미션 요구에 코드 리뷰 이력이 평가 항목으로 들어 있으므로, 규칙이 문서 본문에만 있고 절차에 없으면 FAIL
- **작업**: [T4](M01_잔여작업/T4_테스트_실행과_리뷰_규약.md)

## E. 동결 선언

### E-1. 선언문 커밋
- **검증**: 동결 선언문이 저장소에 존재하고 다음을 포함하는지
  1. **동결 범위** — 어느 타입·어느 어셈블리가 잠기는가, 그리고 **무엇이 잠기지 않는가**
  2. **결정론의 유효 범위** — 동일 바이너리·동일 CPU 아키텍처 내에서만 보장된다는 단서. 이 문장이 없으면 나중에 실기기(ARM64)에서 리플레이가 어긋났을 때 원인을 코어에서 찾다가 시간을 태운다
  3. **변경 절차** — D-2와 동일
  4. **장치 주입의 잠정성** — `Build`의 `injectedLogics`는 장치가 레벨 데이터에서 나올 때까지의 임시 통로다
  5. **충돌 모델의 한계** — 모든 스트로크가 두께 0 의 `EdgeCollider2D` 라 **내부가 없다**는 사실과, solid 가 필요해지면 `PolygonCollider2D` + 볼록 분할로 교체하는 것이 동결 위반이 아니라는 명시
- **통과 기준**: 5가지 전부 포함
- **5번을 넣는 이유**: 질량 특성은 C-6 에서 고쳤지만 충돌 모델은 그대로다. 한계를 적어두지 않고 동결하면 M03에서 프리미티브를 짜는 사람이 **코어 버그로 오인**하거나, 고칠 때마다 동결 위반 여부를 다시 논의하게 된다
- **작업**: [T5](M01_잔여작업/T5_동결_선언.md)
