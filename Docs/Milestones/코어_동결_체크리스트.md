# 코어 동결(Core Freeze) 검증 체크리스트

[M01](M01_결정론_코어와_계약_확정.md) 완료 판정 기준. 통과 시 코어(`SimWorld` / `WorldBuilder` / `Judge` / 계약 타입)를 동결하고 [M02](README.md)에 착수한다.

> **완료 근거 표기 (2026-08-02 감사)**
> 각 항목에 `완료 근거` 를 붙였다. 판정은 셋 중 하나다.
> - **충족** — 코드·테스트가 존재하고 실행으로 확인됨
> - **실행 검증 대기** — 코드는 존재하나 해당 테스트가 아직 한 번도 실행되지 않음
> - **미충족** — 산출물이 없음

## 이 문서의 범위 — 코어 오너가 혼자 끝낼 수 있는 것만

동결의 목적은 **"팀원이 작업을 시작해도 코어가 흔들리지 않는다"를 보장하는 것**이다.
따라서 게이트에는 코어 오너가 단독으로 통제 가능한 항목만 넣는다. 남의 산출물이나 다음 마일스톤의
작업이 섞이면, 코어가 증명 가능하게 옳아도 동결이 되지 않는 교착이 생긴다.

**게이트에서 제외한 것과 그 행선지:**

| 제외 항목 | 이유 | 어디로 |
|---|---|---|
| 팀원 B의 장치 6종 구현 | B의 산출물 | 코어는 최소 장치 하나로 **실행 경로만** 덮는다 ([T3](M01_잔여작업/T3_장치_실행_경로_범위_결정.md)). 6종의 스키마·동작은 B의 작업 |
| 팀원 C의 레벨 에디터 산출물 | C의 산출물 | 코어는 손으로 쓴 샘플 JSON 으로 로더 경로만 증명 ([T2](M01_잔여작업/T2_샘플_레벨_JSON_경로.md)) |
| 벤치마크 3수치·배속 환산 | 코어의 **성능** 특성이지 정확성 특성이 아니다. 동결이 막으려는 것은 정확성 회귀다 | M02 완료 조건 |
| 팀 채널 동결 공지 | 저장소 밖 행위. 게시 여부를 코드로 검증할 수 없다 | 선언문을 저장소에 커밋하는 것까지가 게이트 ([T5](M01_잔여작업/T5_동결_선언.md)) |
| 실기기(ARM64) 재현 검증 | 플랫폼 간 부동소수점 일치는 Physics2D가 보장하지 않는다. 코어 결함이 아니다 | 표본 검증 QA 절차 (설계서 §2.2) |

## 채점 규칙

- 저장소에 **존재하고 실행·확인 가능한 것만** PASS. "구현 예정", "로컬에는 있음"은 FAIL
- 실행형 항목은 **EditMode와 PlayMode 결과를 모두** 제출한다. 결정론·판정·프레임 독립성 테스트는 전부 PlayMode에 있으므로, **EditMode만 초록불인 리포트는 A와 C를 하나도 증명하지 않는다**
- 실행 결과는 통과 개수만이 아니라 **총 개수 / 통과 / 실패**를 함께 적는다. 예외로 죽은 테스트는 "없는 테스트"와 구분되지 않으므로, 총계가 없으면 판정불가로 처리한다
- **커밋된 결과 XML 의 테스트 총계가 현재 테스트 수와 일치해야 한다.** 뒤처진 리포트는 "그 시점의 코드"를 증명할 뿐 현재 코드를 증명하지 않는다
- `판정불가`는 FAIL과 구분해 보고한다 (원인: 환경 부재 / 근거 부재 / 항목 해석 불가)
- **모든 항목 PASS일 때만 동결 가능.** FAIL 항목 목록이 곧 남은 작업 목록이다

## A. 결정론 증명

### A-1. 반복 실행 일치
- **내용**: 같은 `(LevelData, Solution, seed)`로 2회 실행하여 **매 스텝** `WorldHasher.Hash()`가 완전 일치
- **검증**: 아래 매트릭스를 테스트 코드에서 확인 + 실행

  | 케이스 | 입력 | 근거 | 테스트 |
  |---|---|---|---|
  | 1 | 빈 솔루션 | 기준선. 지형·공만으로 갈라지면 그 아래 전부 무의미 | **A-2가 더 강한 형태로 포함** (빈 솔루션 2회 + 사이에 다른 월드) |
  | 2 | 고정선만 | 정적 스트로크 바디가 등록 순서에 끼어드는 경우 | `같은_입력_두_번_실행하면_스텝별_해시가_전부_같다` |
  | 3 | **자유 물체 (접촉 포함)** | 유저가 가장 흔히 그리는 것. 다중 경로 콜라이더·철사 질량 특성·**접촉 해결 순서**가 전부 여기를 지난다. 공중에 뜬 자유 물체로는 접촉 경로를 못 탄다 | `자유_물체가_있어도_같은_입력은_같은_결과다` |
  | 4 | **회전축 포함** | 조인트가 바디 등록 순서에 가장 민감하다 | `회전축이_있어도_같은_입력은_같은_결과다` |
  | 5 | **장치 포함** | 로직 루프와 rng 가 결과에 개입하는 유일한 경로 | `장치가_있어도_같은_입력은_같은_결과다` |
  | 6 | **장치 포함 + 시드 4개** | 시드가 결과에 실제로 **반영되는지**. 같은 시드 재현과는 다른 축이다 | `시드가_다르면_장치_동작이_갈린다` |
  | 7 | **전부 결합** | 개별 케이스가 통과해도 함께 놓였을 때 갈라질 수 있다. 다만 깨졌을 때 원인 특정이 안 되므로 **개별 케이스를 대체하지 않는다** | `FeatureLevelSimTests.전_피처_레벨도_결정론적이다` (L002) |

- **통과 기준**: 케이스 1~5·7은 스텝별 해시 완전 일치. 케이스 6은 반대로 **시드가 다르면 궤적이 갈라져야** 한다 — 시드를 무시하는 코어는 항상 같은 결과를 내므로 나머지 케이스를 완벽하게 통과한다
- **시드 축이 케이스 5·6에서만 의미를 갖는 이유**: 코어에서 `System.Random`이 흘러가는 곳은 `SimWorld.Step()` 의 `_logics[i].Tick(step, _rng)` 한 곳뿐이다. **장치가 없는 레벨에서는 시드가 결과에 닿지 못하므로**, 장치 없는 케이스에 시드를 여러 개 매기는 것은 같은 시뮬을 여러 번 도는 것에 지나지 않는다
- **완료 근거**: **실행 검증 대기.** 7케이스 전부 테스트가 존재하고 이름까지 매핑됐다. `AssertTracesMatch` 가 ① 스텝별 비교 ② 개수 일치 ③ **개수 > 0** 을 모두 단언하므로 공허하게 통과할 여지가 없다. 다만 **케이스 3(`자유_물체가_있어도...`)은 2026-08-02 에 추가되어 아직 한 번도 실행되지 않았다.** 나머지 6케이스는 EditMode 20 / PlayMode 53 시점 실행에서 통과 확인됨

### A-2. 재구축 독립
- **내용**: 같은 입력으로 "생성 → 실행 → 전파괴"를 반복했을 때, 사이에 **다른 월드를 끼워 만들었다 버려도** 매 회차의 스텝별 해시가 1회차와 동일
- **통과 기준**: 전 회차 해시 일치. 회차 수는 3회 이상이면 족하다 — 오염원(정적 카운터·캐시·풀)은 1회차와 2회차 사이에 이미 드러나며, 회차를 늘리는 것으로 새로 잡히는 결함은 없다. 중요한 것은 횟수가 아니라 **사이에 다른 월드를 끼웠는가**다
- **의미**: 되돌리기·재시도·솔버 반복 시도 전체의 기반 증명
- **완료 근거**: **충족.** `DeterminismTests.다른_월드를_사이에_끼워도_재구축_결과가_같다` — 빈 솔루션으로 900스텝 실행 → 다른 레벨(`Gap` + 다리)로 120스텝 → 같은 입력 재실행 후 스텝별 비교. 실행 통과 확인됨. 이 테스트가 A-1 케이스 1도 함께 덮는다

### A-3. 프레임·청킹 독립
- **내용**: 동일 입력을 서로 다른 프레임 간격(30/60/120fps 상당)으로 구동했을 때 도달 스텝과 해시가 일치. 누적기를 거친 결과가 `Step()`을 직접 호출한 결과와 일치. 배속이 스텝 수만 늘리고 내용은 바꾸지 않음
- **통과 기준**: 전부 일치
- **기대치 주의**: 이 항목은 구조상 통과하기 쉽다. `Step()`은 외부 상태를 받지 않고 `Simulate(FixedDt)`만 부르므로 호출을 어떻게 쪼개든 결과가 같다. 실제 위험은 청킹이 아니라 **누적기가 `dt`를 건드리는 것**이고, 그것을 잡는 것은 배속 테스트다. 배속 케이스가 빠져 있으면 FAIL
- **완료 근거**: **충족.** `FrameIndependenceTests` 5개 — 30/60/120fps 해시 일치, 누적기 vs 직접 `Step()`, 일시정지, **배속(요구된 필수 케이스)**, 편집 중 시간 누적 방지. 실행 통과 확인됨

### A-4. 해시 인프라
- **검증**: `WorldHasher`가 **독립 타입**으로 존재하고, 전 바디의 position/rotation/velocity를 **등록 순서 고정**으로 해시하는지 코드 확인
- **통과 기준**: 충족. 테스트 코드에 인라인으로 박혀 있으면 FAIL — 리플레이 실기기 표본 검증과 디싱크 디버깅이 같은 타입을 재사용해야 한다
- **완료 근거**: **충족.** `Assets/_Project/Scripts/Core/Sim/WorldHasher.cs` 로 코어에 독립 존재하며 테스트에 인라인이 아니다. `world.Bodies` 를 **등록 순서 그대로** 순회하고 각 바디의 position / rotation / linearVelocity / angularVelocity / `IsSleeping` 을 **비트 단위**로 섞는다(반올림 비교하지 않음). 파괴된 바디의 null 자리도 `int.MinValue` 로 해시에 반영해 개수 변화를 신호로 남긴다

### A-5. 해시 민감도 ★
- **내용**: 해시가 실제로 월드 상태를 반영하는지. **두 방향 모두** 확인한다
  1. 공 시작 위치를 미세하게(0.0001) 옮겼을 때 궤적이 갈라지는가
  2. **공이 아닌 바디**(공이 닿지 않는 자유 물체)만 옮겼을 때도 갈라지는가
- **통과 기준**: 둘 다 갈라짐. **A-1·A-2·A-3가 이 항목 없이는 성립하지 않는다** — `Hash() => 0` 은 항상 같은 값을 뱉으므로 반복 실행·재구축·청킹 일치를 전부 통과한다
- **2번을 넣는 이유**: 1번만 있으면 **공만 해시하고 스트로크·장치 바디를 통째로 빠뜨린 구현**도 전부 통과한다. 나머지 결정론 테스트는 전부 "같은가"만 보기 때문이다. 그 상태에서는 스트로크가 디싱크해도 아무도 못 잡는다
- **완료 근거**: **실행 검증 대기.** 1번은 `해시는_아주_작은_차이도_잡아낸다` 로 존재하며 실행 통과 확인됨. 2번은 `해시는_공_이외의_바디도_담는다` 로 2026-08-02 에 추가되어 **아직 실행되지 않았다.** 2번 테스트는 조기 종료를 타지 않도록 `SimRunner` 대신 직접 `Step()` 을 200회 돌리고 **길이 일치를 먼저 단언한 뒤** 내용을 비교한다 — 길이 차이만으로 `AreNotEqual` 이 통과하는 것을 막기 위함이다

## B. 계약·격리

### B-1. 계약 타입 확정
- **검증**: `Stroke` / `PivotJoint` / `Solution` / `SimResult`(+`SimOutcome` 4종) / `IStepLogic` / `IStrokeProcessor` / `LevelData`가 `PPS.Core`에 존재
- **통과 기준**: 전부 존재. `SimResult`에 `MinGoalDist` 포함. `IStepLogic`이 `Tick(int step, System.Random rng)` + `HasPendingWork` 형태이고 **경과 시간류 파라미터가 없을 것** (있으면 FAIL — 이 시그니처 자체가 결정론 강제 장치다)
- **완료 근거**: **충족.** `Core/Contracts/` 에 요구된 타입이 전부 파일로 존재한다 — `Stroke` `PivotJoint` `Solution` `SimResult` `SimOutcome` `IStepLogic` `IStrokeProcessor` `LevelData` `ToolType` `DeviceData`. `SimResult` 는 `MinGoalDist` 를 포함하고, `IStepLogic` 은 `Tick(int step, System.Random rng)` + `HasPendingWork` 두 멤버뿐으로 경과 시간 파라미터가 없다. 계약 동작은 `ContractTests`(EditMode 6)와 `ContractSimTests`(PlayMode 1)가 검사하며 실행 통과 확인됨

### B-2. 어셈블리 격리
- **검증**: `PPS.Core.asmdef`의 `references`에 UI·렌더링 어셈블리가 없는지 + 코어 소스에 해당 네임스페이스 `using`이 없는지
- **통과 기준**: 검출 0건
- **참고**: `SimWorld.Dispose()`의 에디터 분기를 제거한 결과 코어의 `UnityEditor` 참조도 현재 0건이다. 다만 이것을 **금지 토큰으로 강제하지는 않는다** (2026-08-01 결정) — 코어에 에디터 전용 디버깅 도구를 붙일 여지를 남긴다. 이 항목은 자동 검사 대상이 아니라 리뷰에서 볼 사항이다
- **완료 근거**: **충족.** `PPS.Core.asmdef` 의 `references` 가 **빈 배열**이다. 즉 UI·렌더링뿐 아니라 **어떤 어셈블리도** 참조하지 않는다. `CoreSourceGuardTests.코어_asmdef가_UI나_렌더링을_참조하지_않는다` 가 asmdef 파일을 직접 읽어 `UnityEngine.UI` / `Unity.RenderPipelines` / `Unity.TextMeshPro` / `Unity.InputSystem` 을 검사한다 — 사람 눈이 아니라 테스트가 지킨다. 실행 통과 확인됨

### B-3. 결정론 금지 API 0건
- **검증**: 코어 소스 전체에서 `Time.time` / `Time.deltaTime` / `Time.fixedDeltaTime` / `Time.timeScale` / `Time.frameCount` / `UnityEngine.Random` / `WaitForSeconds` / `FixedUpdate` / `DateTime.Now` / `Guid.NewGuid` 검색
- **통과 기준**: 검출 0건. 이 검사가 **자동 테스트로** 존재할 것 (사람의 눈으로 훑는 것은 회귀를 막지 못한다)
- **완료 근거**: **실행 검증 대기.** `CoreSourceGuardTests.코어_소스에_결정론_금지_API가_없다` 가 `Core/` 아래 `.cs` 를 전부 읽어 금지 토큰 10종을 검사한다. **주석과 문자열 리터럴을 먼저 제거**하므로 "금지 API 를 설명하는 주석"이 위반으로 오검출되지 않는다. 2026-08-02 에 **"한 파일도 읽지 못하면 실패"** 단언을 추가했다 — 스캔 대상이 비면 위반 목록도 비어 조용히 통과하던 구멍을 막은 것이며, **이 변경분이 아직 실행되지 않았다**

## C. 코어 실행 경로 커버리지

> 동결의 의미는 "이 코드를 더 이상 만지지 않는다"이다. **한 번도 실행된 적 없는 경로를 동결하면,
> 그 경로의 결함은 동결 후에 발견되어 동결을 깨는 변경을 강요한다.** 그래서 코어 안의 분기는
> 동결 전에 실행되었거나, 명시적으로 범위에서 빠져 있어야 한다.

### C-1. 회전축 생성 경로
- **검증**: `CreatePivot`과 그 하위 `Resolve` / `PickHost`가 테스트에서 실제로 실행되는지
- **통과 기준**: 실행됨. 스트로크 간 연결과 `PivotJoint.WorldIndex`(월드 고정) 두 형태 모두 커버. **조인트가 바디를 붙잡고 있다는 직접 검사**가 함께 있을 것 — 조인트 생성에 실패해도 스텝별 해시는 재현되므로 결정론 테스트만으로는 잡히지 않는다
- **완료 근거**: **충족.** `PivotTests` 5개가 두 형태를 각각 덮는다 — `정적_스트로크에_매단_회전축이_바디를_붙잡는다`(`PickHost` 가 정적을 버리고 동적을 고르는 분기), `월드_고정_회전축이_바디를_붙잡는다`(`Resolve` 의 `WorldIndex` 분기). **축에서 바디 중심까지의 거리가 유지되는지**를 직접 재므로 "조인트가 안 만들어졌는데 통과"를 막는다. 대조군 `회전축이_없으면_막대는_그대로_떨어진다` 가 "애초에 안 떨어지는 배치"였을 가능성까지 배제한다. 실행 통과 확인됨

### C-2. JSON → 월드 구축 경로
- **검증**: 저장소에 커밋된 `.json` 파일을 읽어 `LevelData.FromJson` → `WorldBuilder.Build`로 월드가 구축되는지
- **통과 기준**: 성공. JSON에 공 시작점·목표 위치·잉크 제한이 포함될 것 (앵커 생성의 원료). C# 코드로 만든 `LevelData`만으로는 부족하다 — 미션 요구는 **"레벨 추가에 코드 수정이 필요하면 미충족"** 이며, 그 증명은 파일에서 읽는 경로가 있어야 성립한다
- **추가 조건**: 파일의 값이 **하나씩 대조**될 것. `JsonUtility`는 모르는 키를 조용히 무시하고 없는 키를 기본값으로 채우므로 "파싱 성공"만으로는 아무것도 보장되지 않는다. 샘플 값은 `LevelData`의 기본값과 다르게 잡아야 오타가 드러난다
- **완료 근거**: **충족.** 레벨 파일 3개가 커밋되어 있다 — `L001_Ramp.json`(최소, 클리어됨), `L002_Feature.json` + `L002_Feature.solution.json`(표현 가능한 전부). 샘플 값을 기본값과 **일부러 다르게** 잡았다(잉크 14.5/기본 20, 공 반지름 0.28/0.25, 목표 반지름 0.55/0.5, KillY −12/−20) — 키 오타가 조용히 기본값으로 흡수되는 것을 드러내기 위함이다. `LevelJsonTests`(EditMode 4)가 값을 하나씩 대조하고, `LevelJsonSimTests`(PlayMode 4)가 **JSON 값이 실제 콜라이더 반지름까지 반영되는지**와 `Clear` 판정, 왕복 불변을 확인한다. `FeatureLevelJsonTests`(6) · `FeatureLevelSimTests`(5)가 L002 를 같은 방식으로 검사한다. 실행 통과 확인됨

### C-3. 장치 실행 경로
- **결정**: **정식 장치로 도입** (2026-08-01). `LevelData.Devices` 스키마 + `BombDevice` + `DeviceFactory`. 목적이 검증에서 **인수인계**로 바뀌었기 때문이다 — 인터페이스만 있고 구현이 없으면 장치 담당이 결정론 규칙을 코드가 아니라 문서로만 배운다
- **검증**: 다음이 테스트에서 실제로 실행되는지
  - 레벨 데이터의 장치 → `DeviceFactory` → `WorldBuilder`의 등록 루프
  - `SimWorld.Step()`의 로직 루프 (`_logics[i].Tick`)
  - `Judge`의 `HasPendingWork` 분기 — 전 바디가 잠들어도 대기 중인 장치가 있으면 `Stalled`가 미뤄지는가
  - 주입된 `rng`가 소비되고 그 결과가 시뮬에 반영되는가 (A-1 케이스 6)
  - **JSON 파일의 장치**가 파싱되어 로직이 되는가 (C-2와 맞물림)
- **통과 기준**: 위 전부. 모르는 장치 종류에서 **조용히 건너뛰지 말 것** — 레벨 데이터와 다른 월드로 솔버가 "풀린다"고 판정하게 된다
- **장치의 바디**: 장치는 **콜라이더를 가져도 된다.** 장애물·문처럼 물리적 실체가 있는 장치는 바디가 필요하다. 지켜야 할 것은 "만들지 마라"가 아니라 **"정해진 자리에서 만들어라"** 다 — `WorldBuilder`의 고정 순서(공 → 지형 → **장치** → 스트로크 → 회전축)에 이미 그 구간이 있다. 지형 뒤·스트로크 앞이어야 레벨이 만드는 것과 유저가 그리는 것의 경계가 유지된다
- **잠정성 주의**: `DeviceData` 스키마와 `BombDevice` 는 **placeholder** 다. 장치 담당이 자유롭게 바꿔도 되며, 그 변경이 동결 위반이 아니라는 사실이 동결 선언문에 적혀야 한다 → [T5](M01_잔여작업/T5_동결_선언.md)
- **완료 근거**: **충족.** `DeviceTests` 7개가 요구 항목을 하나씩 덮는다 — `레벨_데이터의_장치가_로직으로_등록된다`(등록 루프), `대기_중인_장치가_있으면_전부_잠들어도_Stalled가_아니다`(`HasPendingWork` 분기), `장치가_발동하면_대기가_끝나고_공이_움직인다`(로직 루프), `반경_밖의_물체는_건드리지_않는다`(반경 판정). rng 소비는 `시드가_다르면_장치_동작이_갈린다`(A-1 케이스 6)가, JSON 경로는 `FeatureLevelSimTests.파일의_장치가_로직으로_등록된다` 가 덮는다. 바디를 갖는 장치 경로도 `폭탄이_바디를_가진다` · `폭탄이_터지면_바디가_사라진다` · `파괴_시점이_프레임_분할에_영향받지_않는다` 로 실행된다. `DeviceFactory` 는 모르는 종류에서 `ArgumentOutOfRangeException` 을 던진다. 실행 통과 확인됨

### C-4. 편집↔시뮬 2상태 분리
- **검증**: 편집 상태(월드 없음)에서 물리가 진행되는 경로가 없는지 — **코드 구조 + 자동 테스트**
- **통과 기준**: 월드는 시작 시점에만 생성되고, 월드가 없을 때 전진 호출이 무해할 것. 편집 중 자동 진행 경로가 존재하면 FAIL
- **자동 테스트가 필요한 이유**: 이 규칙을 지키는 실제 장치는 `SimAccumulator.Advance` 의 첫 줄(월드 null 검사) 하나뿐이다. 그 검사가 **누적보다 먼저** 있어야 하는데, 두 줄 순서가 뒤바뀌면 편집 중에 시간이 쌓여 **시작 버튼을 누르는 순간 그만큼이 한꺼번에 터져나온다**(10초 그리다 시작하면 첫 프레임에 600스텝). 코드 구조 검토로는 이 순서 문제를 놓치기 쉽다
- **완료 근거**: **충족.** 구조 — `GameSimDriver` 는 `StartSimulation()` 에서만 월드를 만들고, `Update()` 는 누적기에 넘기기만 한다. `SimAccumulator.Advance` 가 `world == null` 을 **누적보다 먼저** 검사한다. 테스트 — `SimStateTests`(EditMode 2)가 월드 없이 호출해도 0을 반환하고 예외가 없음을, `FrameIndependenceTests.편집_중_흘려보낸_시간은_시뮬_시작_후_한꺼번에_쏟아지지_않는다` 가 5초분(300회) 호출 뒤 월드를 만들어 **첫 프레임에 정확히 1스텝**만 진행되는지 확인한다. 실행 통과 확인됨

### C-5. Outcome 4종 관측
- **검증**: 최소 레벨에서 `Clear` / `Fail` / `Stalled` / `Timeout`이 각각 재현되고, `MinGoalDist`가 **모든 Outcome**에서 초기값(∞)도 NaN도 아닌 값으로 채워지는지
- **통과 기준**: 4종 관측 + `MinGoalDist` 생존. 이 값이 죽어 있으면 M04의 CEM이 학습 신호 없이 헤매게 되고, 그 원인을 솔버 버그로 오인하기 쉽다. 동결 전에 박제한다
- **완료 근거**: **충족.** `JudgeTests` 7개 — `목표에_닿으면_Clear` / `낙사하면_Fail` / `전부_잠들면_Stalled` / `상한에_걸리면_Timeout` 으로 4종을 각각 재현하고, `MinGoalDist는_모든_Outcome에서_채워진다` 가 네 결과 전부에 대해 무한대·NaN 이 아니고 0 이상임을 확인한다. 클리어 케이스는 최소 거리가 목표 반경 근처인지까지 봐서 **계측 시점이 어긋난 경우**도 잡는다. `판정은_한_번_확정되면_뒤집히지_않는다` 가 확정 후 60스텝을 더 돌려도 판정과 `DecidedStep` 이 유지되는지 확인한다. 실행 통과 확인됨

### C-6. 자유 물체가 임의 형상으로 동작한다 ★
- **왜 동결 조건인가**: `ColliderFactory`는 동결 범위 안이다. 그런데 M03 프리미티브(경사면·그릇·상자·바퀴)는 **반드시** 곡선과 닫힌 형태를 전개한다. 이걸 못 다루는 채로 잠그면 M03 착수와 동시에 동결을 깨야 하고, 그건 동결이 아니다

**(1) 충돌** — 자유 물체가 다른 것들과 실제로 부딪히는가

- **Box2D 는 edge ↔ edge 충돌을 만들지 않는다.** 지형·고정선·자유 물체가 전부 `EdgeCollider2D` 이면 자유 물체는 공(원) 말고 아무것과도 부딪히지 않고 지형을 그대로 통과한다
- **검증**: 자유 물체가 ① 지형 ② 고정선 ③ 다른 자유 물체 위에 각각 멈추는지, ④ 공이 자유 물체 위에 얹히는지
- **통과 기준**: 4가지 전부. 기존 테스트가 **공과의 상호작용만** 봐서 이 구멍을 오래 못 잡았다 — 공은 원이라 edge 와 정상 충돌한다. 자유 물체가 주어가 되는 검사가 반드시 있어야 한다

**(2) 질량 특성** — 폴리라인에서도 무게중심과 관성이 맞는가

- 무게중심이 포인트의 산술 평균이 아니라 **선분 길이 비중**일 것 — 같은 형상이 샘플링 밀도에 따라 다르게 움직이면 안 된다
- 관성이 곧은 막대 공식(`m·L²/12`)이 아니라 **선분별 평행축 정리의 합**일 것 — 둘레 `L` 인 고리에서 막대 공식은 약 3.3배 과대다
- 퇴화 스트로크(모든 점이 겹침)에서 관성이 0 이 되지 않을 것 — 0 은 NaN 을 부르고, NaN 은 해시를 타고 번져 원인 추적이 불가능해진다

**통과 기준(공통)**: 위 전부 + **정적 스트로크와 2점 직선 자유 물체의 결과가 이전과 동일할 것.** 이 둘이 흔들리면 기존 레벨·리플레이의 해시 기준선이 통째로 어긋난다. 정적 스트로크를 `EdgeCollider2D` 로 남겨 두는 이유가 그것이다

- **완료 근거**: **충족.** (1) `FreeBodyCollisionTests` 4개가 요구된 4가지를 그대로 덮는다 — 지형·고정선·다른 자유 물체 위에 멈추는지, 공이 닫힌 자유 물체 위에 얹히는지. 전부 **자유 물체가 주어**인 검사다. (2) `StrokeMassTests` 6개가 질량 특성을 검사하며, 기대값은 **손으로 계산한 해석값**을 박아 구현이 자기를 증명하지 않게 했다 — 오른쪽에만 점이 촘촘한 직선의 무게중심이 `x=0`(이전 구현은 `0.3125`), ㄱ자의 관성 `3.333`(막대 공식이면 `5.333`), 정 N 각형의 형상 관성이 해석해 `1 − (2/3)sin²(π/N)` 와 소수점 7자리까지 일치. **직선 불변**은 `직선_자유물체는_막대_공식_그대로다` 와 `같은_직선을_불규칙하게_쪼개도_질량_특성이_같다` 가 지킨다. 퇴화 스트로크 방어는 `ColliderFactory.MinInertia` 로 구현되어 있다. 실행 통과 확인됨

- **통과 기준**: 존재. 미션 요구에 코드 리뷰 이력이 평가 항목으로 들어 있으므로, 규칙이 문서 본문에만 있고 절차에 없으면 FAIL
- **완료 근거**: **충족.** `.github/pull_request_template.md` 존재. 공통 블록(무엇을 바꿨나 + **EditMode·PlayMode 양쪽 총계**)에 더해 **역할별 블록 셋**을 두고 해당하는 것만 남기게 했다 — 화면(스크린샷 · 세로 모드 한 손 조작 · 시뮬 중 그리기 잠금) / 레벨(**빈 솔루션으로 `Clear` 가 나오는지** · 좌표가 JSON 에 있는지) / 코어(계약 사전 공유 · 금지 API · `Step()` 밖 물리 금지 · **리스트 순서 유지**). 코어 항목 중 리스트 순서만 자동 검사가 없어 체크박스의 값이 가장 크다. 동결 이후 리뷰 승인 필수도 명시했다
- **역할별로 나눈 이유**: 팀 4명 중 셋은 코어를 안 건드린다. 코어 항목만 있는 템플릿은 그들의 PR 에서 전부 "해당 없음"이 되고, 그러면 **아무도 안 읽게 되어 정작 필요한 PR 에서도 형식적으로 통과한다**
- **이관 메모**: 이 저장소는 임시다. 실제 저장소가 생기면 `.github/` 를 **파일째 옮긴다.** 이월 관리가 필요 없도록 지금 만들어 둔 것이다(2026-08-02 결정, 대안이던 "실제 저장소로 이월"은 잊힐 위험 때문에 기각)

## E. 동결 선언

### E-1. 선언문 커밋
- **검증**: 동결 선언문이 저장소에 존재하고 다음을 포함하는지
  1. **동결 범위** — 어느 타입·어느 어셈블리가 잠기는가, 그리고 **무엇이 잠기지 않는가**
  2. **결정론의 유효 범위** — 동일 바이너리·동일 CPU 아키텍처 내에서만 보장된다는 단서. 이 문장이 없으면 나중에 실기기(ARM64)에서 리플레이가 어긋났을 때 원인을 코어에서 찾다가 시간을 태운다
  3. **변경 절차** — D-2와 동일
  4. **장치 스키마의 잠정성** — `DeviceType` / `DeviceData` / `LevelData.Devices` / `BombDevice` 는 placeholder 이며 장치 담당이 자유롭게 바꿔도 된다는 것, 그리고 그때 지켜야 할 세 가지(`JsonUtility` 호환 · 리스트 순서 = 난수 소비 순서 · enum 값은 뒤에만 추가)
  5. **충돌 모델의 한계** — 정적은 `EdgeCollider2D`, 동적은 두께를 준 `PolygonCollider2D` 로 **나뉘어 있다는 것**과 그 이유(edge ↔ edge 미충돌), 그리고 **닫힌 형태의 속이 비어 있다**는 잔여 한계. solid 가 필요해지면 볼록 분할로 교체하는 것이 동결 위반이 아니라는 명시
- **통과 기준**: 5가지 전부 포함
- **5번을 넣는 이유**: 질량 특성은 C-6 에서 고쳤지만 충돌 모델의 잔여 한계는 남아 있다. 적어두지 않고 동결하면 M03에서 프리미티브를 짜는 사람이 **코어 버그로 오인**하거나, 고칠 때마다 동결 위반 여부를 다시 논의하게 된다
- **완료 근거**: **충족.** [M01_코어_동결_선언.md](M01_코어_동결_선언.md) 작성. 요구된 5가지를 §1~§5 로 각각 담고, §6 에 판정표와 실행 수치(EditMode 20/20 · PlayMode 55/55, 파일명 포함)를 실었다. 추가로 §3 에 **재실행 조건**(장치 합류 · 형상 변경 · Unity/Physics2D 설정 변경), §7 에 **사람에게 전달할 통보**(C 에게 `LevelData.Devices` 확장 등), §8 에 M02 로 넘길 기지 사항을 남겼다
