## 1. 목표

**"공 하나가 굴러가는 최소 코어"를 만들고, 같은 입력이 항상 같은 결과를 낸다는 것을 자동 테스트로 증명한다.**

완성품을 만드는 단계가 아니다. 장치도 프리미티브도 UI도 없다. 이 마일스톤이 만드는 것은
이후 모든 작업이 올라탈 **바닥**이며, 바닥이 흔들리면 솔버의 판정 결과 전체가 무의미해진다.

동시에 팀 4인이 공유할 **계약 타입을 코드로 확정**한다. 첫 2주 안에 계약이 코드로 서 있지 않으면
팀원 B·C·D가 각자 추측한 인터페이스로 작업을 시작하게 되고, 합류 시점에 전면 재작업이 발생한다.

## 2. 왜 이것이 먼저인가

- 솔버가 성립하는 유일한 조건이 재현성이다. 같은 입력에 결과가 달라지면 "이 레벨은 풀린다"는 판정이 근거를 잃는다
- 결정론 오염은 **나중에 발견될수록 비싸다**. 6주차에 발견하면 그때까지 쌓은 탐색 결과·리포트·리플레이가 전부 폐기된다
- 코어는 팀 4인 전원의 상류다. 늦어지면 팀 전체가 대기한다 (크리티컬 패스)

## 3. 범위

### 3.1 만드는 것

**계약 타입** (`Assets/_Project/Scripts/Core/Contracts/`)

| 타입 | 내용 |
|---|---|
| `ToolType` | `FixedLine`, `FreeBody` |
| `Stroke` | `ToolType Tool`, `List<Vector2> Points` — 단순화 후 포인트. 물리·렌더링·저장이 이 하나를 공유 |
| `PivotJoint` | `int StrokeA, StrokeB`, `Vector2 Anchor` — 포인트가 아니라 연결 정보 |
| `Solution` | `List<Stroke> Strokes`, `List<PivotJoint> Pivots`, `float TotalInk()` |
| `SimOutcome` | `Clear`, `Fail`, `Stalled`, `Timeout` |
| `SimResult` | `Outcome`, `EndStep`, `Stars`, `InkUsed`, `MinGoalDist` (readonly struct) |
| `IStepLogic` | `void Tick(int step, System.Random rng)`, `bool HasPendingWork { get; }` |
| `IStrokeProcessor` | `Stroke Process(ToolType tool, List<Vector2> rawPoints)` — 인터페이스만. 구현은 B |
| `DeviceType` / `DeviceData` | 장치 배치 데이터. `JsonUtility`가 다형 직렬화를 못 하므로 판별자 enum + 파라미터 형태. **장치 담당이 바꿔도 되는 placeholder** |
| `LevelData` | 최소 필드만 (공 시작점, 목표 위치, 지형, 장치, 잉크 제한). C의 확장을 전제로 한 골격 |

`IStepLogic.Tick`의 시그니처에 `deltaTime`이 없는 것이 요점이다. 계약 자체가 결정론 강제 장치다.

**시뮬 실행부** (`Assets/_Project/Scripts/Core/Sim/`)

- `SimWorld` — `FixedDt = 1/60` const, `CurrentStep`, `Step()`(로직 → 물리 → 판정 → 스텝 증가), `IsTerminal`
- `WorldBuilder` — `LevelData` + `Solution` → 격리 씬에 월드 구축. **등록 순서 고정** (장치는 레벨 데이터 순서, 스트로크는 리스트 순서)
- `Judge` — 클리어/실패/정지 판정 + `MinGoalDist` 매 스텝 갱신
- `DeviceFactory` + `BombDevice` — 장치 6종 중 첫 번째이자 **나머지가 참고할 본보기**. 결정론 규칙 네 가지가 이 클래스에 다 들어 있다. 장치 담당이 자유롭게 바꿔도 되는 placeholder ([T3](M01_잔여작업/T3_장치_실행_경로_범위_결정.md))
- `ColliderFactory` — `Stroke` → 콜라이더 GameObject. 이번엔 선분 체인 수준으로 최소 구현
- `WorldHasher` — 전 바디의 position/rotation/velocity 순서 해시 → `ulong`
- 격리 물리 씬: `SceneManager.CreateScene(..., LocalPhysicsMode.Physics2D)`. 실행기 진입점 `Run(level, sol, seed, maxSteps) → SimResult`

**드라이버**

- `GameSimDriver` — 누적기 패턴. `Paused`, `SpeedMultiplier`, 스파이럴 방지 안전장치(`safety < 8`)
- (`SolverRunner`는 M02 범위)

**어셈블리 분리**

- `PPS.Core.asmdef` (계약 + 시뮬 실행부) — UI·렌더링 어셈블리를 참조하지 않는다
- `PPS.Core.Tests.asmdef` (EditMode) — 월드가 필요 없는 검사. 계약 타입, 코어 소스 정적 가드
- `PPS.Core.PlayTests.asmdef` (PlayMode) — 시뮬을 돌리는 검사. 결정론·판정·프레임 독립성. `WorldBuilder`가 쓰는 `SceneManager.CreateScene`이 런타임 전용이라 이쪽에 있어야 한다
- `PPS.Core.TestFixtures.asmdef` (전 플랫폼, 테스트 메서드 없음) — 위 둘이 공유하는 테스트 레벨
- **asmdef는 코어와 테스트에만 둔다.** 게임·UI·장치 코드는 `Assembly-CSharp`에 둔다. asmdef 어셈블리는 `Assembly-CSharp`를 참조할 수 없어서, 게임 쪽까지 asmdef로 쪼개면 팀원 전원이 asmdef를 만들어야 하는 상황이 된다. 얻는 것(컴파일 시간)보다 잃는 것(팀 마찰)이 크다
- 코어 asmdef 하나로 "코어는 프레임을 모른다"는 이미 컴파일 에러로 강제된다. 규칙을 사람의 주의력에 맡기지 않는 것이 목적이고, 그 목적은 어셈블리를 더 나눈다고 더 달성되지 않는다

**결정론 자동 테스트** — 아래 §4 참조

### 3.2 이번에 만들지 않는 것 (명시적 범위 밖)

- 솔버, 프리미티브, CEM, 난이도 측정 — M03 이후

- 잉크 파이프라인 단순화 알고리즘 (`IStrokeProcessor` 인터페이스만, 구현은 B)

- 드로잉 UI, 튜토리얼, 자동 저장
- 헤드리스 CLI, 벤치마크 — M02
- 다각형 분할(자유 물체의 닫힌 형태) — 최소 코어에는 불필요. M03에서 프리미티브가 요구할 때 추가

## 4. 완료 조건 (DoD)

전부 만족해야 M01 완료다. 하나라도 미충족이면 M02에 착수하지 않는다.

표기: `[x]` 구현 완료 + 테스트 통과 / `[~]` 구현·테스트 코드 작성 완료, **실행 검증 대기** / `[ ]` 미착수

- [~] **결정론 테스트 초록불** — 같은 `(level, solution, seed)`로 2회 실행하고 **스텝별** `WorldHasher.Hash()` 를 비교해 전 구간 완전 일치. 최종 상태만 비교하지 않는다 (중간에 갈렸다가 우연히 수렴하는 경우를 놓치고, 무엇보다 갈라진 첫 스텝을 특정할 수 없어 디버깅이 막힌다) → `DeterminismTests`
- [~] **프레임 독립 테스트** — 30/60/120fps 상당의 경과 시간 시퀀스로 구동했을 때 도달한 스텝 수와 해시가 동일 → `FrameIndependenceTests`
- [~] **월드 재구축 테스트** — 사이에 다른 월드를 하나 끼워 만들었다 버린 뒤 재구축해도 첫 실행과 해시 단위로 일치 (되돌리기·초기화·재시도의 근거) → `DeterminismTests.다른_월드를_사이에_끼워도_재구축_결과가_같다`
- [~] **조기 종료 판정 동작** — `SimOutcome.Stalled`(전 바디 sleep + `HasPendingWork` 없음)가 실제로 잡히고, `MinGoalDist`가 **모든 Outcome**에 대해 채워짐 → `JudgeTests`
- [~] **`Run(level, sol, seed, maxSteps) → SimResult`** 시그니처로 최소 레벨이 Clear·Fail·Stalled·Timeout 네 가지를 모두 재현 → `JudgeTests`
- [x] **계약 타입이 `PPS.Core` asmdef에 존재**하고, UI·렌더링을 참조하지 않음이 어셈블리 설정으로 강제됨 (+ 코어 소스에 결정론 금지 API가 없는지 정적 검사 — `CoreSourceGuardTests`)
- [x] 팀원 B·C·D가 계약 타입을 참조해 각자 작업을 시작할 수 있음 → [팀_인터페이스_계약.md](../팀_인터페이스_계약.md) (합의는 공유 후)

### 실행 검증에서 먼저 깨질 만한 곳

위험도 순으로 적어 둔다.

1. ~~**EditMode에서 `SceneManager.CreateScene`이 동작하는가**~~ — **결론: 동작하지 않는다.** 2026-07-31 실행에서 26개 중 17개가 `InvalidOperationException`("This can only be used during play mode")으로 실패했다. 월드를 만드는 테스트를 PlayMode 어셈블리로 옮겨 해결했다
2. **램프 레벨의 공이 실제로 목표까지 구르는가** — 각도·마찰을 계산이 아니라 추정으로 잡았다. `TestLevels.RampToGoal()` 좌표 조정으로 해결
3. **프레임 독립 테스트의 스텝 수가 정확히 일치하는가** — 부동소수점 누적이 예상대로 떨어지는지에 달렸다
4. **`FreeBody`의 질량·관성** — `EdgeCollider2D`는 면적이 없어 자동 질량이 0이라 직접 넣었다. 값이 부적절하면 NaN이 난다

## 5. 작업 순서

1. 폴더·asmdef 골격 생성 (`PPS.Core`, 테스트 3종) + 참조 차단 확인
2. 계약 타입 작성 → **팀에 먼저 공유**. 구현보다 계약이 우선이다 (팀 병렬성 확보)
3. 격리 물리 씬 생성/파괴 + `SimWorld.Step()` 최소 골격. 이 시점에 "공 하나가 떨어진다"까지
4. `WorldBuilder` — 등록 순서 고정. `Stroke` → 콜라이더 최소 변환
5. `WorldHasher` + 결정론 테스트 작성. **여기서 한 번은 깨질 것이다** — 깨진 원인을 찾는 것이 이 마일스톤의 본체다
6. `Judge` — 클리어/실패/`Stalled`/`Timeout` + `MinGoalDist` 계측
7. `GameSimDriver` 누적기 + 프레임 독립 테스트
8. **잔여 작업** — [M01_잔여작업/](M01_잔여작업/README.md) T1~T4
9. 코어 동결 선언 (§7)

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| 결정론이 첫 시도에 안 잡힘 (가장 가능성 높음) | 스텝별 해시로 **갈라진 첫 스텝**을 특정한 뒤 그 스텝의 로직만 역추적. 최종 상태만 비교하면 이 디버깅이 불가능해진다 — 그래서 스텝별 해시가 DoD에 있다 |
| 팀원이 무심코 `Time.deltaTime`/`UnityEngine.Random`을 코어에 유입 | asmdef 참조 차단 + 결정론 테스트를 상시 회귀 감시로 운용. CLAUDE.md에 금지 목록 명시 완료 |
| 에디터(x64)와 실기기(ARM64)의 부동소수점 비트 불일치 | M01 범위 밖. 대표 풀이 리플레이를 실기기에서 재생하는 **표본 검증**을 QA 절차로 편입 (설계서 §2.2). 발표 시연 자료로도 사용 |
| 계약 타입이 나중에 흔들려 팀 재작업 발생 | 2주차 안에 코드로 확정하고 동결. 변경 시 결정론 테스트 + 리뷰 필수 |
| 최소 코어를 만들다 완성품을 만들려는 유혹 | 범위 밖 목록(§3.2)을 기준으로 판단. 장치·UI·다각형 분할은 이번에 손대지 않는다 |

## 7. 완료 후 — 코어 동결

동결 판정은 [코어_동결_체크리스트.md](코어_동결_체크리스트.md)로 한다. 남은 작업은 [M01_잔여작업/](M01_잔여작업/README.md)에 T1~T5로 쪼개 두었다.

DoD 충족 시 코어(`SimWorld` / `WorldBuilder` / `Judge` / 계약 타입)를 **동결**한다.
이후 변경은 다음을 모두 거친다.

1. 결정론 테스트 재실행 초록불
2. 코드 리뷰 (형상관리 요구사항 — 리뷰 이력이 평가 항목)
3. 계약 타입 변경 시 영향받는 팀원에게 사전 공유

동결 후 곧바로 **M02 (헤드리스 호스트 + 조기 종료 + 벤치마크 실측)** 에 착수한다.
설계서의 예산·상한 수치(회차 300/700/1,000, 스텝당 0.1~0.3ms 등)는 전부 추정치이며,
M02의 실측이 나오기 전까지는 어떤 계획 수치도 확정으로 취급하지 않는다.
